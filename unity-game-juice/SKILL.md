# Unity 游戏动态反馈

沿用现有 Work Item、Implementation Package 与 V0–V4 阶段，不创建反馈专用状态机或 Work Item 类型。场景与显示层仍逐阶段提交产物并等待用户确认。

玩法角色拥有权威状态、命中/伤害判定、事件语义、数值和动作触发。本角色把已确认的玩法事件映射为表现通道及生命周期策略；表现反馈不能作为玩法判定依据。顿帧、击退等会改变规则或玩家控制的行为由玩法与数值角色确定，本角色只实现其已批准的表现部分。

## 工作流程

1. **V1 明确反馈意图**：对核心事件记录玩家应理解的信息、触发时机和预期感受，并确定视觉、音频、镜头、时间与交互反馈是否适用。此处与美术 brief、主题和可读性目标一致。
2. **V2 冻结事件映射**：为每个事件记录来源、参数、表现通道、强度、时长、触发条件、时间来源、优先级、重复/叠加策略、中断处理、完成行为及负责对象。具体格式见[动画意图与反馈时间轴合同](../unity-development-workflow/references/animation-intent-contract.md)。
3. **V3 组合正式资源**：消费已登记的动画、VFX、音频和镜头参数，在真实 Scene/Prefab/UI 组合中检查触发次序、层级、遮挡和时间行为；记录 Unity 实测与资源引用。
4. **V4 验收动态体验**：按[美术质量契约](../unity-development-workflow/references/art-quality-contract.md)检查适用的正常游玩、重复反馈、事件峰值和同屏叠加情境。真实运行片段和人工检查绑定当前工作项、候选与场景；技术验证不代替用户对显示效果的确认。

## 必须明确的运行行为

- **重复**：同一事件再次触发时，声明重播、重置、合并、限频或忽略等策略，并说明选择理由。
- **叠加**：声明并行、合并、限量或优先级规则，避免多个反馈争用同一属性或遮蔽玩法信息。
- **中断与收尾**：声明被更高优先级事件打断、对象禁用、关闭显示层或离开场景时如何结束；结束后恢复被临时修改的视觉属性。
- **时间与暂停**：按反馈通道声明使用缩放时间或非缩放时间，以及暂停、顿帧和 UI 交互时的行为。不得让一个短暂反馈意外改变全局 `Time.timeScale`；修改全局时间的玩法规则由玩法角色持有。
- **对象生命周期**：对象池复用前清除旧动画、计时器、协程、事件订阅和临时状态；释放后不得继续播放或影响新实例。选择适合项目实现的清理方式并在实际对象池轨迹验证。

反馈设计需服从[美术质量契约](../unity-development-workflow/references/art-quality-contract.md)的可读性与观看舒适要求。HUD、Toast、奖励浮字等若含玩家可见文字，按[游戏内文案指导](../unity-development-workflow/references/game-copy.md)消费已冻结表达与真实事件数据，不添加未批准的解释语句，并保留图标控件的项目级无障碍名称。需要制作不同动画路线时，按[动画意图与反馈时间轴合同](../unity-development-workflow/references/animation-intent-contract.md)明确资产负责人；生产级模型与贴图 Skill 不承担动画生产。
