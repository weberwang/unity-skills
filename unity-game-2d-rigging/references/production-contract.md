# 制作与交接合同

本合同把项目需求变成可检查的角色资产与接口。它沿用控制面现有 Work Item、实施单元、Implementation Package、证据与门禁，不定义独立资产状态机。

岗位所有权、动画质量负责人和分阶段交接按[2D 动画岗位协作](../../unity-development-workflow/references/2d-animation-collaboration.md)执行。总控在既有实施包明确独立的质量负责人，设计前提供动作标杆、代表动画与批量接入时提交专业审查材料；TA 提供公共工具与技术规范，骨骼角色继续负责实际角色制作与返修。专业审查、工程结果和用户视觉确认分别记录，不另建审批流程。

## 开工信息

按项目读取并记录：

- 当前 Work Item / 实施单元、允许路径、资源所有权、基线与验收范围。
- Unity、已解析包、渲染管线、可复用 Editor、实际命令目录、资源导入设置及 asmdef 边界。
- 完整角色图的路径、来源、许可、SHA、尺寸、透明通道和参考姿势；它是拆解基准，不是正式 Sprite。
- 已确认的视角、方向、角色朝向、镜像许可、非对称道具和翻面后的层叠规则。
- 每个动作的真实使用场景：相机视角、目标显示尺度、角色职责、操作频率、速度与接触约束、事件时机，以及循环、过渡、中断和消费者。
- 像素尺寸、PPU、根原点、骨骼命名、资源目录，以及经项目批准的骨骼、网格、纹理和性能预算。

缺失的普通技术细节可以形成有依据的方案并记录；视觉、玩法公开接口或性能放行上的实质取舍交回总控。动作需求由当前玩法合同决定，不默认生成人形动作清单。

正式部件生产前，先用隔离技术样例或已验收可复用部件验证最小资产链路，覆盖创建、保存、重载、变形与动画播放。当前角色正式部件须先通过拆件确认，能力验证不得依赖仍待确认的正式部件；样例通过只证明链路可用，不代表当前角色动作或视觉效果通过。

## 视角与方向选择

先复用项目或用户已经确认的有效决定。没有决定时，在拆件和骨架设计前由总控让用户选择；输入图的视角不自动决定游戏角色视角。

| 选项 | 需记录的信息 |
| --- | --- |
| 横版侧视 | 默认左右朝向、镜像许可及左右不对称部件 |
| 正面 | 背面可见性、转身需求和前后遮挡 |
| 四分之三视角 | 可见侧、透视比例、远近肢体层叠 |
| 俯视 | 俯视角度、可见方向与方向部件 |
| 等距斜视 | 项目投影规则、方向集合、地面接触和挂点投影 |
| 自定义或组合视角 | 每个稳定视角 ID、适用场景、切换规则与独立动作范围 |

观察视角与角色朝向是两个字段。俯视或斜视不自动代表四方向或八方向；方向集合、镜像和独立制作范围由项目决定。所选视角和源图不一致时，先让视觉资产角色补齐对应基准图，再制定拆件合同。

## 部件生产合同

逐部件保存结构化映射。至少包含：

- 稳定基础部件 ID、变体 ID、角色源图版本 / SHA、视角 ID、方向、用途和生产边界。
- 输出画布与透明尺寸、角色局部坐标、Pivot、像素尺寸、朝向、PPU 和目标资源身份。
- 遮挡补全范围、关节连接区、边缘要求、前后层叠顺序与检查姿势。
- 绑定后关联的骨骼 / 父级、部件刚性或连续变形方式、换装或挂点关系。

骨骼父子关系表达运动依赖；渲染排序表达遮挡关系，两者分别记录。视觉资产角色生产独立部件图和连接区，检查来源与映射；不得直接裁切完整效果图冒充独立 Sprite。任何图像生成或编辑由 `image_generator` 子代理执行。

### 动画与部件组合要求

拆件方案定稿前，由骨骼角色与玩法角色共同评审并记录根节点和朝向、挂点名称及局部空间、动画事件语义与消费者、位移归属。骨骼角色拥有骨架、网格、权重、Clip 和角色 Animator Controller 内部状态、参数、过渡与中断；玩法角色拥有权威玩法状态、规则和触发时机，只消费双方约定的接口。按此划分避免 Controller 内部表达与玩法规则互相覆盖。

每个动作都按实际使用场景规划起势、发力/执行、接触或事件点、收势/恢复及循环或中断节奏，按动作意图决定哪些段落适用。需考虑相机视角、游戏中的实际显示尺度、角色职责、玩家操作频率、动作速度、接触反馈、事件时机和可读性约束；逐个动作确定总时长、FPS、关键姿势和事件时间，不套用通用模板、预制节拍或统一时长。详细字段沿用[动画意图与时间轴合同](../../unity-development-workflow/references/animation-intent-contract.md)。

代表动画按最可能暴露缺陷的风险选择，覆盖高风险关节弯折、遮挡顺序变化、挂点/道具跟随、高速动作与接触等适用项。若简单待机无法覆盖当前风险，在同一代表动画预览验收中补充必要姿势或短片段，不另加审批阶段。实际 Unity 预览在约定视角和显示尺度检查；截图与片段由用户人工检查，代理不得自动分析截图或将自动检查结果表述为视觉通过。

部件必须在约定的视角、动作范围和显示尺度内组合无缝。拆件时预留足够的关节覆盖和运动余量，补全会在转动/遮挡中露出的内部区域；保持边缘颜色、纹理、轮廓线连续。所有部件遵循统一的 PPU、角色局部坐标和根节点约定；各自的 Pivot 按映射对齐关节，不要求使用相同数值。检查透明边缘采样、网格/权重变形及渲染排序在运动全程的衔接。验收排除裂缝露底、连接错位、重叠双轮廓和明显接缝；不得靠缩小画面、改变机位或放宽容差来掩盖问题。若发现缺图或绘制问题退回视觉资产角色；若为骨架、网格、权重或动画导致则由骨骼角色修复。

### 图像变体闭环

小幅弯曲、拉伸和摆动优先用现有骨骼、网格与权重完成。若动作需要的角度、透视、轮廓、手势、表情或遮挡变化无法由变形正确表达，骨骼角色应主动提出新增角度图、替换图或必要的过渡图，不得为迁就旧图而强拉变形。变体数量按实际动作需要确定，不要求每帧一张图，也不以生成式整段动画替代 Unity 骨骼动画。

拆件时先规划已知的图像变体；动画制作中发现现有图片不足，则沿用当前 Implementation Package 与资源登记完成闭环，不新增 schema 或状态：骨骼角色说明缺口及用途，视觉资产角色基于已确认基线组织生产，由 `image_generator` 实际生成或编辑，骨骼角色接入变体、设置切换并重验受影响内容。变体记录应明确基础部件 ID 与变体 ID、用途角度或形变、消费动作及姿势/切换时机、连接区相邻部件、输出画布/PPU/Pivot/角色局部空间、替换目标与切换驱动所有权、来源及 Sprite 资源身份，以及默认姿态和退出、打断、对象池重置行为；继续使用现有映射与登记位置。

每个变体都要实际验证能否复用基础部件的骨骼网格和权重；尺寸、轮廓或拓扑不适用时，重新制作匹配的网格/权重并验证，不得盲目复制。骨骼角色拥有 Clip、Controller 内部结构及角色图像切换；玩法角色不得直接切换 Sprite，除非双方已约定接口并明确单一写入者，玩法状态和规则仍由玩法角色负责。

在变体切换前、切换瞬间和切换后检查轮廓与比例、关节连接、颜色与纹理、渲染排序、运动轨迹和挂点连续，确保无跳变、裂缝或露底。使用正常速度预览，并在必要时慢放检查；视觉效果由用户人工检查，代理不得自动分析截图或据此判定通过。

拆件合同确定后直接制作并确认真实 Unity 代表动画；不额外设置动画灰盒阶段，也不因合批生产强迫动作等长或同步。

## 两次版本绑定确认

**拆件确认**必须展示在冻结基准图上真实可查看的框选标注，标明部件、连接区、遮挡补全、层叠、骨架运动方向和生产边界；对应的稳定映射与资源规格另存为内部合同。确认绑定当前角色、源图基线、拆件版本和用户回复。用户要求修改时先修正与复验，再展示新版本；确认前不开始正式部件生产。

**代表动画确认**必须在真实 Unity 角色播放后展示，覆盖主要运动和能暴露连接问题的姿势。确认绑定相同角色、基线、骨架 / 部件版本、预览版本和用户回复。该确认发生在扩展其余动作之前；修改要求先修正、复验并展示新预览。

已确认拆件生产边界内、为满足已确认动作而补充的角度图或变体，按上述闭环直接制作、接入、展示并复验，不增加文字审批。若变体引入新的视角方向或超出已确认拆件生产边界，先更新并重新展示受影响的拆件内容，获得确认后再正式生产。若补件改变已确认代表动画，则先展示更新后的代表动画并获得确认，再扩展依赖该动画的动作。

确认对象清楚且唯一时，用户针对已展示交付明确回复“确认”“通过”或“继续”可按控制面规则处理；沉默、自动化 PASS、测试结果或另一代理意见不构成确认。专项确认通过现有实施包 / 证据产物引用已确认对象版本、用户回复和交付，不添加 schema 字段。若本任务属于 `SCENE` / `DISPLAY_LAYER`，遵循现有 V0–V4 与 `stageReviews` 门禁：拆件内容一致时可并入 V2，代表动画仍需在批量制作前确认；同一回复可覆盖多个已清楚展示的对象，但必须分别记录确认范围。专项确认不创建新阶段、字段或 schema。

向用户提交 V2 交付时遵守现有视觉工作流的展示格式；身份、版本、验证结果和确认范围按该工作流放在图内。其他 Work Item 遵循自身现有门禁，不套用场景状态。

## Unity 与玩法交接

交给玩法角色的合同至少包括：

- Prefab 路径与 GUID / 资源 ID、根节点、坐标 / 朝向 / 缩放规则和复用生命周期。
- Animator Controller 路径、参数名称与类型、动作到 Clip / 状态的映射、循环、过渡与中断约定；该 Controller 内部结构由骨骼角色维护，Controller 不持有权威玩法状态，玩法角色经约定接口驱动它。
- Animation Event 的名称、参数、时间点和语义；伤害、命中、移动与战斗判定由玩法实现。
- 挂点路径及局部空间定义、适用朝向、启停规则，以及本资产已知限制。

资产交付前，QA 独立检查部件映射、边缘与连接区、全运动范围的绑定/变形/层叠、动画、挂点、引用生命周期、Prefab 重载和项目批准预算，并在约定尺度检查实际 Unity 预览。通过此轮后可标明资产就绪并交玩法接入；该结果不代表整体完成。

交接同时执行[骨骼资产交付门禁](../../unity-game-workflow-control/references/rigging-delivery-gate.md)：在现有工作项和证据的 `riggingDelivery` 绑定当前角色、Prefab/GUID、候选修订、负责人和实际必需回归。独立 QA 保存当前工程报告及目标项目正式角色 Editor PlayMode 原始结果；任一失败、未执行、缺失、陈旧或对象不符都阻断交玩法，静态 F3 PASS 和公共技术夹具不构成替代。工程报告任务 ID 对应当前 Work Item，返修后取得受影响内容的新证据，不能沿用旧版本报告。

玩法接入后，QA 再按玩法合同检查游戏内实际响应及其次数和时机、事件次数和时机、移动与接触结果，以及状态交接和适用的中断、暂停恢复、对象池复用、多实例隔离。只有相关接入检查完成，才能提供整体完成证据。缺陷按责任返修：缺失部件、遮挡补全或绘制边缘问题由视觉资产角色处理；骨架、网格、权重、Clip 和 Controller 内部问题由骨骼角色处理；触发、玩法状态、判定、位移规则和事件消费问题由玩法角色处理。跨界问题交总控裁决责任和范围；修复后重验受影响的 Clip、Prefab、导入引用和相关 QA 项，未受影响内容不要求重做。

两轮检查均提供真实资产、真实 Unity 预览与可复验依据，并将两轮预览交用户人工检查；未执行检查标为 `NOT_RUN`，缺少必需能力或输入而无法检查标为 `BLOCKED`，实际检查失败标为 `FAIL` 并修复。不把说明文档或自动工具结果当作资产交付或视觉验收。
