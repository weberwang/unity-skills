# 制作与交接合同

本合同把项目需求变成可检查的角色资产与接口。它沿用控制面现有 Work Item、实施单元、Implementation Package、证据与门禁，不定义独立状态机或新 schema。

## 开工信息

按项目读取并记录：

- 当前 Work Item / 实施单元、允许路径、资源所有权、基线与验收范围。
- Unity、已解析包、渲染管线、可复用 Editor、实际命令目录、资源导入设置及 asmdef 边界。
- 完整角色图的路径、来源、许可、SHA、尺寸、透明通道和参考姿势；它是拆解基准，不是正式 Sprite。
- 已确认的视角、方向、角色朝向、镜像许可、非对称道具和翻面后的层叠规则。
- 角色部件运动方式、动作清单、节奏、循环、过渡、中断、事件语义、挂点和消费者。
- 像素尺寸、PPU、根原点、骨骼命名、资源目录，以及经项目批准的骨骼、网格、纹理和性能预算。

缺失的普通技术细节可以形成有依据的方案并记录；视觉、玩法公开接口或性能放行上的实质取舍交回总控。动作需求由当前玩法合同决定，不默认生成人形动作清单。

## 视角与方向选择

先复用项目或用户已经确认的有效决定。没有决定时，在拆件和骨架设计前由总控让用户选择；输入图的视角不自动决定游戏角色视角。

| 选项 | 需记录的信息 |
| --- | --- |
| 横版侧视 | 默认左右朝向、镜像许可及左右不对称部件 |
| 正面 | 背面可见性、转身需求和前后遮挡 |
| 四分之三视角 | 可见侧、透视比例、远近肢体层叠 |
| 俯视 | 俯视角度、可见方向与方向部件 |
| 等距斜视 | 项目投影规则、方向集合、地面接触和挂点投影 |
| 自定义或组合视角 | 每个稳定视角 ID、适用场景、切换规则与独立动作范围 |

观察视角与角色朝向是两个字段。俯视或斜视不自动代表四方向或八方向；方向集合、镜像和独立制作范围由项目决定。所选视角和源图不一致时，先让视觉资产角色补齐对应基准图，再制定拆件合同。

## 部件生产合同

逐部件保存结构化映射。至少包含：

- 稳定部件 ID、角色源图版本 / SHA、视角 ID、方向、用途和生产边界。
- 输出画布与透明尺寸、角色局部坐标、Pivot、像素尺寸、朝向、PPU 和目标资源身份。
- 遮挡补全范围、关节连接区、边缘要求、前后层叠顺序与检查姿势。
- 绑定后关联的骨骼 / 父级、部件刚性或连续变形方式、换装或挂点关系。

骨骼父子关系表达运动依赖；渲染排序表达遮挡关系，两者分别记录。视觉资产角色生产独立部件图和连接区，检查来源与映射；不得直接裁切完整效果图冒充独立 Sprite。任何图像生成或编辑由 `image_generator` 子代理执行。

## 两次版本绑定确认

**拆件确认**必须展示在冻结基准图上真实可查看的框选标注，标明部件、连接区、遮挡补全、层叠、骨架运动方向和生产边界；对应的稳定映射与资源规格另存为内部合同。确认绑定当前角色、源图基线、拆件版本和用户回复。用户要求修改时先修正与复验，再展示新版本；确认前不开始正式部件生产。

**代表动画确认**必须在真实 Unity 角色播放后展示，覆盖主要运动和能暴露连接问题的姿势。确认绑定相同角色、基线、骨架 / 部件版本、预览版本和用户回复。该确认发生在扩展其余动作之前；修改要求先修正、复验并展示新预览。

确认对象清楚且唯一时，用户针对已展示交付明确回复“确认”“通过”或“继续”可按控制面规则处理；沉默、自动化 PASS、测试结果或另一代理意见不构成确认。专项确认通过现有实施包 / 证据产物引用已确认对象版本、用户回复和交付，不添加 schema 字段。若本任务属于 `SCENE` / `DISPLAY_LAYER`，遵循现有 V0–V4 与 `stageReviews` 门禁：拆件内容一致时可并入 V2，代表动画仍需在批量制作前确认；同一回复可覆盖多个已清楚展示的对象，但必须分别记录确认范围。专项确认不创建新阶段、字段或 schema。

向用户提交 V2 交付时遵守现有视觉工作流的展示格式；身份、版本、验证结果和确认范围按该工作流放在图内。其他 Work Item 遵循自身现有门禁，不套用场景状态。

## Unity 与玩法交接

交给玩法角色的合同至少包括：

- Prefab 路径与 GUID / 资源 ID、根节点、坐标 / 朝向 / 缩放规则和复用生命周期。
- Animator Controller 路径、参数名称与类型、动作到 Clip / 状态的映射、循环、过渡与中断约定。
- Animation Event 的名称、参数、时间点和语义；伤害、命中、移动与战斗判定由玩法实现。
- 挂点路径及局部空间定义、适用朝向、启停规则，以及本资产已知限制。

QA 独立检查部件映射、绑定、极端姿势、动画、引用生命周期、实例隔离和项目批准预算。向下游提供真实资产与可复验依据：未执行检查标为 `NOT_RUN`，缺少必需能力或输入而无法检查标为 `BLOCKED`，实际检查失败标为 `FAIL` 并修复；不把说明文档当作资产交付。
