# V1–V4 阶段人工确认

本规则适用于独立 `SCENE` 和 `DISPLAY_LAYER` Work Item。V0 仅作内部识别与分流，不请求常规人工确认，也不写入 `stageReviews`。工作项只在 V1–V4 设置阶段审查；V4 的实际运行交付经用户确认后，才可完成工作项。

纯工程 `FOUNDATION` 没有视觉依赖时不等待全局视觉基线选择。若当前实施包声明 `visualBaselineRequired=true`，则必须先引用有效的全局视觉基线选择证据。

## 阶段交付与确认

| 阶段 | 提交用户确认的交付 | 确认后的边界 |
| --- | --- | --- |
| V0 分流 | 不提交常规确认；内部确定工作项身份、范围、上下文、依赖与验收目标 | 条件满足后进入 V1 |
| V1 对象定义 | 视觉工作项的真实完整目标图及简短检查点；确认图成为 V2–V4 的持续目标。功能、状态、结构和 Unity 原生响应式合同在内部记录 | 确认后进入 V2 拆解 |
| V2 拆解与布局 | 先展示带稳定编号和中文标注的拆解图并确认；再生成并单独展示布局图、参照和关键约束并确认 | 两项确认都有效后进入 V3 正式资源生产 |
| V3 正式资源验收 | 可放大的正式资源及来源、导入和验证结果；可选展示临时组合预览和 V1 对照 | 确认后进入 V4 正式 Scene/Prefab/UI 实现与校准 |
| V4 实现与运行验收 | 实际 Scene/Prefab/UI 组合、交互和运行证据、V1 对照、已知未还原项与限制 | 用户确认后完成当前场景或显示层工作项 |

普通图片任务直接制作并展示真实候选，不增加文字方案审批。动画是例外：开始制作动画素材前，先说明设计理念与动作方案，等待用户明确确认；制作完成后仍须展示真实动画素材或运行预览供验收。既有骨骼拆件与代表性动画等专项确认继续执行，不替代 V1–V4 阶段确认。

阶段交付必须可查看、可核对，注明工作项、阶段、交付版本、验证结果和待确认范围。不得只提交计划或“已完成”文字。机器检查和 Unity 技术 `PASS` 不能代替用户判断显示效果；V4 缺少真实 Unity 运行证据时，不能靠人工确认通过。

V3 只完成正式资源生产、导入、登记及资源级验收。临时组合预览可用于查看资源关系，但不得在 V3 完成正式 Scene/Prefab/UI 接入或布局校准。正式组合和校准在 V4 进行。V3/V4 对照沿用[视觉交付规则](../../unity-development-workflow/references/visual-workflow.md#v3-正式资源生产与导入验收)，不得用后续生成图替换 V1。

## 确认记录

`Work.stageReviews` 只允许 `V1`、`V2`、`V3`、`V4`，不得为 V0 创建记录。V1、V3、V4 的阶段条目使用 `confirmation`；V2 阶段条目分别使用 `decompositionConfirmation` 和 `layoutConfirmation`。这三个对象均包含同一组字段：

| 字段 | 含义 |
| --- | --- |
| `workItemId` | 被确认的独立工作项 |
| `stage` | 被确认阶段；V2 的两项都为 `V2` |
| `confirmedBy` | 实际确认用户的身份记录 |
| `confirmedAt` | 明确确认的 ISO 时间 |
| `userMessageRef` | 可追溯到用户明确回复的消息引用 |

V2 必须先取得 `decompositionConfirmation`，之后才能生成并提交布局图；再取得 `layoutConfirmation`。布局确认时间不得早于拆解确认。V2 两项确认都有效后，才算阶段闭合。确认记录还应定位用户实际查看的交付并关联必要验证结果，不生成阶段或候选 SHA。

追溯沿用 `userMessageRef` 定位的原交付消息，以及当前工作项关联的实施包、Manifest 和实际产物引用。原消息应能找回用户看到的图和当时的验证材料；不在 `confirmation` 内新增 schema 未定义的产物字段。控制器不能读取或证明消息内容，消息与真实交付的对应关系由编排者核实。

确认记录只能在收到用户针对当前交付的明确回复后写入，不能自动生成批准人、时间或消息引用。控制器校验字段、工作项、阶段及先后关系；编排者核对消息确实来自用户。初始任务授权、历史确认、沉默、超时、工具成功、测试 `PASS`、代理自评或另一代理的消息都不构成当前确认。

场景与显示层分别确认；确认宿主场景不会确认其显示层。一次回复可以确认多个已展示对象，但必须分别记录各自工作项与阶段。阶段确认和 A4–A6 外部操作审批分别记录，阶段通过不授权付费、外部写入、真机、上传或发布。

## 阶段推进与失效

`scene-stage --to V1|V2|V3|V4 --work-item <file>` 只允许同一工作项相邻推进。推进前必须闭合当前阶段要求的产物、证据和确认；V0 无确认门。V3→V4 还要求 Evidence 为 `PASS` 且当前执行单元全部闭环。推进时清除不再由新阶段消费的旧引用、归档旧执行状态、将新阶段设为 `PROPOSAL`、重置 F2/F3/F4；编排者随后冻结并显式绑定新阶段实施包，补齐当前门禁后由 `run` 进入实施。V2 两项确认任一缺失都不能推进。

已确认目标内的实现调整不自动使确认失效。工作项身份、已确认目标或实际范围发生实质改变时，仅重做受影响阶段；证据过期使用 `revalidate`，字段或绑定错误使用 `repair`。只有上游事实失效或范围变化才 `return`，并按受影响范围推导恢复点。不得通过改写历史确认掩盖偏移。

待确认是正常门禁，不是失败验收。显示“等待 Vn 人工确认”，保留当前交付、版本和证据；不能把工作项标记完成，也不能以空确认记录继续推进。
