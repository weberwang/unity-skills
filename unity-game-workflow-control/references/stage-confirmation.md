# V0–V4 阶段人工确认

适用于每个独立 `SCENE` 和 `DISPLAY_LAYER` Work Item。每个阶段先完成产物和必要验证，再展示给用户并等待明确确认。V0 确认后进入 V1，依次推进；V4 确认后才可闭合工作项。阶段内部的可逆实施、修复和验证仍按已授权范围自动执行。

## 确认内容

| 阶段 | 提交用户确认的内容 | 确认后的边界 |
| --- | --- | --- |
| V0 分流 | 工作项身份、范围、宿主上下文、依赖、验收目标 | 开始 V1 场景定义 |
| V1 场景定义 | 完整效果图与简短检查点；确认图持续作为 V2–V4 视觉目标，功能、状态、结构和响应式技术记录内部保存 | 开始 V2 拆解 |
| V2 拆解确认 | 图片框选与图内中文标注，展示节点与资源拆解、来源、装配、所有权和生产边界 | 开始 V3 正式资源生产与组合 |
| V3 资源与组合验收 | 可放大的正式资源画廊、V1 与当前实际同屏组合的可查看对照、已知未还原项；引用/导入验证记录内部保存 | 开始 V4 正式接入与运行验证 |
| V4 实现与运行验收 | 最终交互、画面、生命周期、运行证据、V1 与当前组合的可查看对照、已知未还原项和限制 | 完成当前场景或显示层工作项 |

提交物应可查看、可核对，注明工作项、阶段、交付版本、验证结果和下一阶段范围。不得仅给计划或“已完成”文案就请求确认。验证失败先在当前阶段修复，缺少必要证据时不提出阶段通过；V4 缺少真实 Unity 运行证据时不能用人工确认代替验证。

V3/V4 对照沿用[视觉交付规则](../../unity-development-workflow/references/visual-workflow.md#v3-正式资源与组合验收)，不能用后续生成图替换 V1；同风格、工程 PASS 或阶段确认不免除对原目标的持续核对。源素材检查与运行截图人工验收按[追溯与检查边界](../../unity-development-workflow/references/art-quality-contract.md#追溯与检查边界)区分，代理先查漏补缺，再供用户判断实际显示效果，不新增确认轮次。

图片与动画遵守[图片优先的确认方式](simplified-workflow.md#图片优先的确认方式)。阶段内部的拆解分析、布局决策、提示词和动画时间轴由代理直接维护并制作真实候选，不追加制作前文字方案确认；实际交付确认不再重复确认文字复述。用户要求返修时，在原目标范围内直接修复与重验，展示前后对照；决定性歧义只暂停受影响内容，不能取消前序阶段或真实素材确认。

V2 拆解说明只直接展示图片，不另行输出文本段落、表格、编号清单或代码块；上述身份、版本、验证结果和待确认范围写入图内。框选编号与内部结构化合同逐项对应，验收以实际交付及已确认要求为准，详见[图片框选与标注交付](../../unity-development-workflow/references/visual-workflow.md#图片框选与标注交付)。

## 人工确认来源

- 仅接受用户针对已展示的当前阶段交付明确表达的确认。对清晰、单一的待确认对象回复“确认”“通过”“继续”可以作为确认；同时存在多个对象时必须明确适用对象，不能扩大解释。
- 初始任务授权、要求全自动完成、历史阶段确认、沉默、超时、工具成功、测试 PASS、代理自评或另一代理的消息，都不是当前阶段人工确认。
- 场景与显示层分别确认；确认宿主场景不会确认其弹窗。一次回复可以明确确认多个已展示对象，但必须分别记录各自阶段与版本。
- 待确认时停留在当前阶段，不开始下一阶段生产、写入或验收。可回答问题、整理当前交付和执行只读调查，不能借准备工作提前实现下一阶段。
- 用户要求修订尚待确认的交付时，完成修改与重验，再展示最终结果供确认。已确认目标内的实现调整不自动使确认失效；已有确认可复用，不因文件内容或合同版本变化重复询问。
- 阶段确认与 A4–A6 精确外部审批分别记录。阶段通过不授权付费、外部写入、真机、上传或发布。

## 控制面记录

Work Item 使用 `stageReviews` 数组保存 V0–V4 阶段和人工确认。每个条目包含 `stage`，用户确认后才添加 `confirmation`：

| confirmation 字段 | 含义 |
| --- | --- |
| `workItemId` | 被确认的独立工作项 |
| `stage` | 被确认阶段 |
| `confirmedBy` | 实际确认用户的身份记录 |
| `confirmedAt` | 明确确认的 ISO 时间 |
| `userMessageRef` | 可追溯到用户明确回复的消息引用 |

记录用户实际查看的交付位置、完成情况和必要验证结果，不生成阶段或候选 SHA。合同保留实施前的目标与边界；目标内的实现调整在实际交付或验收记录说明即可，无需回改合同或逐字段对齐，不得改写历史确认以掩盖视觉偏移。

确认记录只能在收到用户回复后写入，不得自动生成批准人、时间或虚构消息引用。控制器验证记录形状与绑定，无法自行证明消息确实来自用户；编排者必须核对实际对话来源并保留可追溯记录。

进入 V1–V4 时，所有前序阶段必须具有属于该工作项和阶段的确认。当前阶段出现 PASS 产物/证据或进入 PASSED 等收敛状态时，也必须确认当前交付；V4 未确认不能进入 COMPLETE。`check`、`run` 和显式正常状态迁移均不得绕过此门。控制器不自动修改视觉阶段，编排者更新阶段记录后仍需运行 `check`。

## 修改与失效

以实际要求是否仍满足判断确认有效性。工作项身份改变、用户撤回确认或实质改变已确认目标时，重新确认受影响部分；范围内实现调整、合同内容或版本变化、文件替换和单纯重跑验证不自动撤销确认，不要求重走前序阶段。行为改变后补做受影响验证，实际失败的结果不能继续作为通过证据。

待确认是正常的人工门，不是失败验收。显示“等待 Vn 人工确认”，保留当前产物、版本和验证证据；不得标记整个工作项完成或通过空的确认记录继续推进。
