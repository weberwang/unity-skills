# 最小 Git 提交集

阶段验收达到 `PASS` 后，由主代理自动创建本地阶段提交。提交只包含当前阶段运行/构建所需文件，以及恢复当前工作项所必需的记录和实际引用文件。长期保存、已确认或位于特定目录都不自动构成提交理由；未入库也不构成删除理由。本规则不改变文件位置、确认权威、阶段门或当前任务范围。

## 纳入依据

| 类别 | 选入依据 |
| --- | --- |
| 运行与工程文件 | 当前源码、实际加载的正式资源及 `.meta`、构建/平台配置、依赖清单与锁文件、必要工具和验证当前改动所需的测试 |
| 当前规格 | 当前阶段实际使用的项目配置、GDD/TDD、视觉与布局合同、资源清单、来源与许可依据；按文件选择，不整目录提交 `docs/` |
| 续接记录 | 当前 Work Item、绑定的实施包、必要执行状态/单元结果、差异审计、有效确认与证据索引，以及仍参与当前决定的委派、变更和审批记录 |
| 实际引用产物 | 上述有效记录及规格引用的图片、视频、布局包、生成/归一化记录、截图、录屏、日志和必要源输入；按实际引用递归检查到没有缺项 |

当前范围包含本次阶段工作项以及其仍有效引用的全局、宿主、共享模块和其他工作项文件。完成的旧工作项只在仍被引用时纳入；同目录下无引用的历史任务不随提交自动进入。当前证据引用多张候选时，纳入保持选择可复核所需的完整候选集合和记录。

机器记录、证据路径与人工产物遵循[产物存放规则](../../unity-development-workflow/references/artifact-storage.md)：`Artifacts/reviews/` 和 `Artifacts/validation/` 是人工查看的产物位置，不是机器 `evidenceRoot`。受 `evidenceRoot` 约束的 Manifest 文件列表、`files`、`outputFile` 等字段仍只能写入工具当前指定的实际机器根；人工路径只能通过允许该类引用的业务字段关联。已冻结的记录不为提交而迁移或重写。

通常不纳入临时尝试、无有效引用的失败候选/旧版本/重复预览、无后续用途的源素材、缓存、普通调试日志、进程锁、已完成事务的临时文件、依赖安装目录和可再生成构建输出。若其中的媒体或日志仍为当前门所需的实际文件，则按引用纳入；不能只留下路径字符串。秘密、凭据、个人数据和未脱敏日志不得因引用关系加入提交。

## 忽略与精确放行

使用[项目忽略模板](../assets/minimal-project.gitignore)合并到目标项目 `.gitignore`，保留已有且仍有效的项目规则，不整体覆盖。模板默认忽略临时、源文件、人工产物、文档和控制记录中的文件，同时保持父目录可遍历；它不自动识别引用，也不自动暂存文件。执行代理按当前有效引用逐文件添加以 `/` 定位的 `!` 例外。

- 父目录须先可遍历，逐文件放行才有效。不要使用 `!/.workflow-control/**`、`!/docs/**`、整个 Work Item 目录或通配符代替经过核对的精确文件清单。
- 例外路径使用项目相对路径与 `/`。含 Git 通配符的文件名按 Git literal pathspec 规则转义；暂存时同样逐个使用 literal 路径，防止路径扩大范围。
- 检查最终忽略效果，而非只读根 `.gitignore`：对每个候选文件检查 `git check-ignore --no-index -v -- <path>`，并用 `git ls-files --cached -- <path>` 核对已有跟踪状态。Git 忽略规则不影响已跟踪文件。
- 不再需要且明确属于当前工作项的既有跟踪文件，只有在确认无有效引用后才可按精确路径移出索引；不批量整理历史跟踪状态，不运行 `git clean`，不使用 `git add -f` 绕过规则。

例外语法示意如下；不得把示例路径当成固定必需清单：

```gitignore
# 工作流必要文件开始
!/docs/TDD.md
!/.workflow-control/work-items/WI-1.json
!/.workflow-control/evidence/WI-1/execution-state.json
!/.workflow-control/evidence/WI-1/units/result-1.json
!/.workflow-control/evidence/WI-1/attachments/V4/run-1/test.log
!/Artifacts/reviews/WI-1/V2/candidate-1/review.html
!/Artifacts/reviews/WI-1/V2/candidate-1/layout.png
!/Artifacts/validation/WI-1/V4/run-1/screenshot.png
!/Artifacts/validation/WI-1/V4/run-1/test.log
!/docs/confirmed/scenes/battle/layout-target/v1/layout.png
# 工作流必要文件结束
```

## 提交闭环

1. 阶段 `PASS` 后，主代理从当前 Work Item、实际规格、入口与测试证据出发，结合字段语义递归追踪实际引用，包括 HTML/CSS/JSON 内嵌资源、图像/视频引用、生成记录、构建输入和 Unity `.meta` 配对。`allowedPaths`、未来预期输出、示例命令、失效占位路径不自动构成提交依据；动态加载无法确定时检查实际加载路径。
2. 确认事务已结束、必要记录可一致读取、当前必需文件真实存在；缺失时先修复或明确阻塞，不能删除引用、跳过门或说“以后可生成”来缩小提交。
3. 合并当前有效且归属清楚的精确例外，逐路径复核忽略和已跟踪状态。并行工作留下的有效例外不得覆盖或清除。
4. 检查提交前的暂存区。若已暂存内容包含其他工作项或归属不明的更改，保留他人暂存状态，不执行本阶段提交，并报告阻塞原因；不得擅自取消他人的暂存。
5. 仅按明确文件路径暂存当前阶段集合与必要 `.gitignore` 变化，不运行 `git add .`、`git add -A` 或全量路径暂存。检查 `git diff --cached --name-status` 和实际差异；确认所有有效引用文件已在当前提交或既有 Git 历史中。
6. 创建本地提交并记录 Git 提交身份、必要文件范围、验证结果和本地遗留项。若仓库 Git 身份未配置，不得伪造身份；保留已验证的文件选择并报告原因。
7. 提交后复核 HEAD 与工作区状态。不得自动推送、改分支、创建 worktree、运行真机、删除本地保留产物或执行其他未授权外部操作。

若无法在不触碰他人改动的前提下形成干净提交，阶段内容可保持已验收，但提交状态必须报告为未完成；修复归属或暂存边界后再完成本地提交闭环。
