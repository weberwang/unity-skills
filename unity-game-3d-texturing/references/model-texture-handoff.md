# 建模与贴图交接

建模与贴图均通过 Blender MCP 生产，沿用既有 Work Item、Implementation Package、资源 ID 与 V0-V4/F2/F3，不新增交接状态机或用户确认阶段。此清单是两角色的共同交接依据：建模角色提交真实产物，贴图角色只读核对并记录实际接收的来源。

存在角色绑定或动作时，另读[3D 角色共同交接](../../unity-development-workflow/references/3d-character-handoff.md)。建模负责几何/UV/法线/槽位和静态源；绑定负责骨架/权重与角色蒙皮模型导出，动画负责同骨架的动作文件。贴图保持所有这些结构只读，使用共同约定的参考网格/姿态烘焙，不用当前播放帧的变形结果替代烘焙基准；Unity 角色导入按[角色导入合同](../../unity-development-workflow/references/3d-character-unity-import.md)执行。

## 建模提交与贴图接收

| 交接项 | 建模交付 | 贴图核对与用途 |
| --- | --- | --- |
| 身份与文件 | 资源 ID、当前模型候选、版本化 `.blend`、运行时导出文件、对象/Collection 名称、源与导出实际位置 | 绑定实际模型/UV 来源、目标对象与 Unity 资源；不能仅凭文件名或“最新版”猜测 |
| 最终网格 | 运行时低模、变换、Pivot、拆件边界、修改器/三角化、硬边、法线/切线生成或导入策略 | 烘焙使用与运行时一致的网格、UV、法线及三角化；不得在贴图阶段改拓扑、重新平滑或重算法线 |
| UV 与纹理集 | 实际 UV 通道、岛/接缝、允许重叠区域、Texel Density、Padding、材质槽到纹理集的对应及 UV 报告 | 只读核对拉伸、重叠、越界、密度与用途；针对镜像烘焙或 UDIM 明确可消费方案，不静默重排或重展 UV |
| 投射输入（按需） | 对应高低模、匹配命名、Cage 源及使用规则、必要的隔离/爆炸烘焙分组 | 配置投射和采样参数；Cage 或结构不合格退回建模，不修改交付的 Cage 网格补救 |
| 槽位与 LOD | 材质槽名称、顺序、面分配、各 LOD 用图策略与碰撞代理标识 | 向既有槽位赋材质，不增加/删除/重排槽位或改变面分配；确认每级 LOD 共用 UV/图集还是需独立贴图；碰撞代理不参与外观烘焙 |
| 动画前置（按需） | 蒙皮、骨架、BlendShape、顶点顺序约束与动画生产者 | 全部只读，贴图不能改变绑定或变形数据；本角色不接管动画制作 |
| 外观与预算 | Visual Bible、目标机位/观看距离、表面分区、必须建模与可贴图细节、平台和内存预算、已知问题及许可 | 确定 Shader、通道、分辨率/位深、透明与细节尺度；需求与模型矛盾时定位责任并退修 |

高模/Cage/动画等不适用项说明原因，不为满足清单虚造产物。模型仍为 blockout、UV/法线/槽位缺陷未解决、实际导出与源不一致或关键输入缺失时，贴图接收为受影响步骤 `BLOCKED`；不得先制作正式纹理再用暗改模型补齐。

## 写入所有权

- 建模角色拥有生产几何、UV、法线、材质槽结构、LOD、碰撞及静态模型导出；角色的骨架/蒙皮模型由绑定角色导出，按角色共同交接保持同一网格基准。贴图角色拥有纹理派生 `.blend` 的材质节点、蒙版、绘制图、烘焙设置、PBR 图像和通道打包。Texel Density 与 Padding 的目标共同商定，模型 UV 修正归建模，烘焙膨胀边与像素处理归贴图。
- 原始模型只读。贴图使用版本化派生文件或只读链接输入，派生文件中的网格也不得改变；只可给既有槽位赋材质，不能把派生网格重新导出覆盖运行时模型。
- 建模与贴图不同时写同一 `.blend`、输出目录或 Unity 对象；共享文件由总控指定唯一写者串行交接。Unity Material/TextureImporter 与资源级 Prefab 的写入也按实施包串行进行，正式场景装配属于 V4。
- 保存贴图源时保留可编辑节点和全部图像依赖，记录被外链/打包的实际路径；不得让未保存的内存图像、临时路径或建模工作目录中的未交付文件成为唯一来源。

## 缺陷退回与局部重验

退回时给出资源 ID、实际源路径、对象/UV 通道/槽位/LOD、预期与实际问题、受影响贴图或烘焙区域及建议修复，沿用现有 `repair`/`return` 规则。建模修复后提交更新的源与导出、受影响范围和技术记录；贴图只读重新接收，再修复相关产物，不要求回改合同或计算 SHA。

| 实际变化 | 必须重验的依赖 |
| --- | --- |
| 仅颜色、粗糙度或遮罩调整，网格/UV/烘焙输入未变 | 受影响主通道、打包图、Material、Importer 和显示结果；不无故重烘全部通道 |
| 几何、三角化、法线/切线、高模或 Cage 改变 | 相关 Normal/AO 等投射图、依赖这些图的蒙版与材质、通道打包及 Unity 接入；按实际依赖确定重烘范围 |
| UV、纹理集、槽位结构/面分配或 LOD 用图策略改变 | 受影响纹理的映射、绘制、烘焙、打包、Renderer/LOD 与 Prefab 引用；旧贴图不得直接宣称适配新模型 |
| 仅 Collider、资源命名/路径或 Unity GUID 改变 | 按实际变化验证碰撞或资源引用；只有影响烘焙对象选择、身份或输入时才重做相关烘焙 |

## 贴图交回与共同完成

贴图交回模型候选与 UV 来源、可编辑纹理 `.blend` 和依赖、主通道/打包图、烘焙与打包配方、槽位/LOD/Shader 映射、实际导出文件、Unity Importer/Material/GUID 与资源级 Prefab 结果。建模侧核对几何与槽位未被贴图改写，独立 QA 核对实际依赖与技术证据。

技术结果、独立 F2/F3 与用户显示确认分别记录。转台、线框、UV 棋盘、近远景、掠射光和目标场景截图只供用户人工检查；除非明确要求自动验证，不自动分析截图或判定视觉通过。正式场景在 V4 验证，未经明确要求不启动 Standalone/Player 或真机。
