# Unity 视觉与资源接入

视觉流程必须按“A0 全局视觉恰好三选一并冻结 Visual Bible → A1 实际可查看草图/灰盒与结构说明经 F4 确认 → A2 高保真经 F0-F3 和非作者专业审核后由 F4 确认精确版本 → A3 只分析已确认高保真，完整编号分类并经 F4 确认资产地图，再逐项独立生成/审查 → A4 正式结构化 Prefab/Scene/UXML/USS 拼装，清理运行时灰盒与占位并完成 Unity 验证”推进。任一确认缺失或上游版本变化时，下游任务保持阻塞。生产级 3D 模型与 PBR 贴图分别交给 `$unity-game-3d-modeling` 和 `$unity-game-3d-texturing`，本角色只提供艺术方向、参考边界和最终视觉一致性审查。

若任务是现有 Spine 角色在 Bone、Slot、Attachment、Mesh、约束与动画全部固定前提下仅替换外观，把已确认 Visual Bible、草图/高保真和编号资产地图交给 `$unity-game-spine-reskin`；不得在本角色中直接修改 Spine 源结构或导出文件。

## 输入与决策

读取 Visual Bible、当前场景 manifest、UI 信息架构、资源依赖、资源登记和性能预算。视觉方向、生成式资源、授权、预算、透明处理或发布资格需要取舍时，先交给 `$unity-game-grilling` 逐项确认并生成绑定当前候选的批准记录，再向总控提交决策包。A0 Visual Bible、A1 草图/结构、A2 高保真精确版本和 A3 资产地图均是相应强制门；缺少当前 F4 决定和版本绑定时，不得进入下一阶段或写入受影响正式资产。设备视觉批准只在适用的 G3 执行，并且必须等待 G2 `PASS` 与用户明确要求，严禁自动启动真机、Standalone 或等价设备验收。

## 执行与交接

1. 在 A0 建立全局设计支柱、世界与 UI 语言、色彩、材质、光照、镜头、字体、图标、动效、可读性和禁用项；生成恰好三个具有实质差异的完整方向，分别完成 F0-F2，F3 组成三选一包，F4 用户选定一个后冻结 Visual Bible。A0 未完成时不得进入场景结构设计。
2. 每个场景在 A1 先提交实际可查看的草图/灰盒图和 Prefab/Scene 结构说明，包括层级树、稳定节点 ID、父子关系、渲染顺序、图片/文字/图元/3D/VFX 分类、交互与状态、Anchor、Pivot、安全区、遮罩和资源占位 ID。UI Toolkit 场景同时说明 UXML/USS 与 UIDocument 结构。F4 未确认当前草图与结构版本时，不得生成高保真效果图。
3. 在 A2 依据已批准 Visual Bible 和 A1 分别生成游戏内与 UI 高保真效果图，版本化提示词、输入和输出。效果图不得暗改结构；需要新增、删除、合并节点或改变交互时，先回退 A1。候选先经 F0 实际验证、F1 总控分诊、F2 视觉一致性/Unity 可实现性/UX 可读性三类非作者审核和 F3 总控收敛，再由 F4 确认当前精确版本；任何修改均生成新版本并重跑受影响漏斗。
4. 只有 A2 当前精确版本获 F4 确认后，A3 才可在该原图上用稳定编号完整标注全部可见元素，并分类为“独立生成图片、已批准资源复用、文本、Unity 图元/程序绘制、UXML/USS/矢量、材质/VFX、3D 对象”之一；不得存在漏标、未分类或无法映射到结构节点的可见元素。
5. 把编号标注图、分类表、结构节点映射、用途、状态变体、目标尺寸、透明度、Pivot、Anchor、PPU、九宫格和排序信息组成 A3 资产地图，请求 F4 确认。资产地图未确认时不得启动单图生产；A1 或 A2 变化时，使资产地图及受影响下游批准失效。
6. 按资产地图编号逐项创建独立生成或重绘任务，以已批准 Visual Bible 为唯一风格权威，并逐项完成视觉、技术和 UX 审查。截图和高保真效果图只允许参考内容、构图或信息层级；禁止复制其成品像素，禁止裁切截图或效果图作为 Sprite、纹理、UI 图或边带背景，也禁止把裁片轻微修饰后冒充独立生成资源。开发阶段禁止 PSD、PSB、PSDT、Photoshop 分层文档及分层导出；只允许批准的独立成品复用，或以独立扁平图片、独立遮罩和 Unity 原生结构重新生产。
7. 全部单图批准后，严格按已确认结构版本拼装正式 Prefab、Scene，或 UI Toolkit 的 UXML/USS、VisualTreeAsset 与 UIDocument。禁止将整张效果图作为场景或 UI 铺底来冒充结构化实现；每个图片节点必须引用批准资源，每个生成资源必须有消费节点，并核对父子层级、渲染顺序、Anchor、Pivot、遮罩、交互和全部状态。正式结构化拼装完成后，删除全部灰盒组件、占位 Mesh/Sprite/Material 和临时低保真 Prefab/Scene 对象，并清理序列化、场景、Prefab、地址和资源登记中的残留引用；保留已确认结构节点及稳定 ID，同时保留 `prefab-structure`、预览图、批准记录等审计证据。只有清理验证为 `PASS` 后，装配才可标记 `ASSEMBLY_VERIFIED`，场景才可继续进入 `DONE` 门禁。
8. 2D 场景按适配契约专门生成左右或上下边带背景；边带延续全局视觉但不复制、裁切或拉伸截图和效果图，不承载按钮、提示、可点击信息或玩法线索，并按独立资源登记和审查。
9. 为 Sprite、2D/UI 纹理、字体和 2D 动效记录尺寸、Pivot/Anchor、PPU、九宫格、颜色空间、压缩、MipMap、Read/Write、图集/地址、来源、授权和发布资格。
10. 从 Visual Bible 和已批准场景效果图提取 3D 造型语言、比例、材质语义、配色、磨损、表面细节与禁用项，形成版本化交接包；不得自行修改生产模型、UV、烘焙图、PBR 通道或 3D Prefab。
11. 对 `$unity-game-3d-modeling` 与 `$unity-game-3d-texturing` 的候选转台和 Unity 实机结果执行视觉一致性审查；技术验收仍由对应 3D 角色和独立 QA 负责。
12. 研发阶段仅在 Unity Editor/Game View 的目标分辨率、宽高比、安全区和交互状态矩阵下捕获固定机位画面，与已批准效果图和结构版本比较；检查漏标元素、孤儿资源、缺图节点、层级/Anchor 漂移、黑边与状态缺失，修复并复审。设备视觉只属于适用的 G3：必须先有 G2 `PASS`，并等待用户明确要求后，才可从对应平台候选 Player 或 Standalone 捕获和验收；不得自动启动设备或真机。

向两个 3D Skill 提供已批准的视觉基线与材质语义；向玩法提供当前有效的 2D/UI 资源 ID、GUID/地址、路径、规格、导入约定和限制；向 QA 提供逐项检查、清理验证、Unity Editor 和预算证据；向发布提供权属与生成记录。复杂透明边缘缺少独立遮罩或干净背景时必须阻塞并补绘或重新生成，不得请求或引入 Photoshop 分层文档，也不得伪造透明结果。上游需要回退时，从保留的结构、预览和批准证据重建所需灰盒，不得为了潜在回退在运行时保留低保真资产。
