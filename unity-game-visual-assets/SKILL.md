# Unity 视觉与资源接入

视觉流程按“全局确认 → 每场景游戏效果图 → UI 效果图 → 实机对比”推进；每个小循环都经独立审查和用户批准。

## 输入与决策

读取 Visual Bible、当前场景 manifest、UI 信息架构、资源依赖、资源登记和性能预算。视觉方向、生成式资源、授权、预算、透明处理或发布资格需要取舍时，向总控提交决策包。

## 执行与交接

1. 先建立全局色彩、材质、光照、镜头、字体、图标、UI 密度和禁用项；生成独立方向图，三类审查迭代后请求用户批准。
2. 每个场景分别生成游戏与 UI 效果图；版本化提示词、输入和输出，按视觉一致性、Unity 可实现性、UX/可读性意见迭代到用户批准。
3. 包含多个元素的效果图进入总控资源流水线：登记查重、拆分前审查、生成/拆分、逐项检查、Unity 导入/场景验证和登记更新。效果图不得直接冒充运行时资源。
4. 为 Sprite、纹理、模型、字体、动画和 VFX 记录尺寸、Pivot/Anchor、PPU、九宫格、颜色空间、压缩、MipMap、Read/Write、图集/地址、来源、授权和发布资格。
5. 捕获 Windows 实机画面，与已批准效果图比较；修复资源或实现并重新捕获、复审，直到用户批准。

向玩法提供当前有效资源 ID、GUID/地址、路径、规格、导入约定和限制；向 QA 提供逐项检查、Unity 运行和预算证据；向发布提供权属与生成记录。复杂透明边缘缺少分层源或遮罩时必须阻塞，不伪造透明结果。
