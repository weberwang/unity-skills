# Blender MCP 生产级角色绑定流程

绑定在既有 V0–V4 和当前 Work Item 内完成，不建立额外的角色资产状态、阶段或审批。模型和贴图事实以[3D 角色交接](../../unity-development-workflow/references/3d-character-handoff.md)为准；Unity 侧的模型导入、Avatar、SkinnedMeshRenderer、Prefab 与播放检查以[Unity 角色导入流程](../../unity-development-workflow/references/3d-character-unity-import.md)为准。

## 开始条件与能力发现

绑定输入至少能唯一确定：角色资源 ID、Visual Bible/参考许可、模型 `.blend` 与网格版本、各 LOD 对应关系、单位/前向/上向、静置姿势、网格对象/材质槽、UV 和法线/切线约定、已有 BlendShape 目标几何、目标平台预算、目标 Unity 项目、预期动作/重定向用途与输出根。缺少影响骨架形态、变形范围或导出结构的事实时，仅阻塞受影响内容并向总控指出缺项。

- 先复用 Blender 进程与 MCP 会话，核对 Blender 及 MCP 版本、活动文件、数据块、未保存更改、对象/Collection、外链和文件可重开性；确认源、派生工作区、输出路径与单写者后再修改。
- 通过当前工具描述与版本 API 逐项核实 Armature/骨骼编辑、权重读写及统计、姿势/约束/驱动、逐帧烘焙、FBX 导出与回读能力。不要假定 MCP 某个专用工具存在，也不要把可运行脚本当作完整生产能力。
- 脚本执行服从现有精确授权边界；已有授权必须明确覆盖本次脚本、目标对象与路径，否则先展示脚本并取得确认。只允许约定范围内 Blender 数据操作及源/派生保存、导出；不调用 shell、网络、环境变量、凭据或无关文件访问。
- 当前能力无法可靠创建、编辑、烘焙或回读所需产物时，相关工序记为 `BLOCKED`；不能以 Unity 自动权重、Unity 里临时补骨、2D 骨架流程、外部 Rig 自动化或供应商代替 Blender 源生产。

## 所有权与输入冻结

1. 对照共享交接只读检查网格版本、拓扑/顶点顺序、法线、UV、材质槽、BlendShape 名称/目标几何以及 LOD 映射；保留原模型与纹理来源及关联信息。导出前后回读这些数据，证明绑定没有污染它们。
2. 将形态问题（轮廓、关节体积、拓扑或目标几何）退回建模；将 UV、槽位、颜色或 Shader 信息问题退回模型/纹理负责人。只有骨架布局、静置姿势、权重、Rig 关系、校正驱动和导出骨骼选择由绑定处理。
3. 冻结目标动作范围、关节活动范围、道具/特效挂点和可选面部通道，以及每个 LOD 的变形与预算要求。以版本化派生文件工作，不修改原始网格或绑定输入。

批量绑定全角色或扩展到所有 LOD 前，按[Unity 导入合同的导出基准与回读要求](../../unity-development-workflow/references/3d-character-unity-import.md#导出职责与统一基准)选择一个代表网格/LOD，实测拟用蒙皮算法、一个压力姿势及必要校正驱动/已交付形态通道：经实际 Blender MCP 导出和目标 Unity 导入后，回读权重、变形与通道结果。需要形态曲线时，按合同显式携带同源形态网格并验证目标几何和权重曲线，不能默认纯骨架文件可承载它；能力未通过时阻断依赖该能力的批量生产。

## Rig 与蒙皮工序

| 工序 | 必须完成的工作 | 退出证据 |
| --- | --- | --- |
| 绑定设计 | 从角色比例、动作范围、游戏视角、道具和重定向需求决定骨架方案；明确根骨/骨盆关系、静置姿势、命名、局部轴向、bone roll、父子层级及必需挂点。将 deform、控制、机制和辅助骨分类 | 版本化骨架表和姿势/轴向说明；骨架覆盖需要表达的关节，控制骨不冒充运行时变形骨 |
| 静置姿势与骨架 | 在 Blender MCP 中建立并检查 rest pose 与 Armature。规划 root（供 Unity 角色位移语义使用）、骨盆/脊柱、四肢、头部、尾/翅/附肢和按需的辅助关节；骨名和层级稳定、可识别。结构由实际角色决定，不强制套用标准人形 rig | 骨架层级、方向和静置姿势可读；每个 LOD 的蒙皮网格及挂点有明确骨架映射 |
| 控制系统 | 依表演需求制作 IK/FK、 pole、伸展限制、空间/父级切换和便于动画师操作的控制器；记录控制骨、变形骨和机制依赖。约束或驱动若不能由目标 Unity 运行时直接表达，须在动画生产中烘焙为可读骨骼/形态曲线 | 代表姿势可控、约束无循环/跳变、控制层与导出 deform 层分明；控制器不被误导出为动画骨骼 |
| 蒙皮权重 | 自动权重、热扩散或权重转移只能作为初始候选；按角色关节体积、拓扑和真实运动范围手工修正并检查跨部件/穿透。按已选运行时和平台预算确定影响骨数，不强制统一的四影响限制 | 每个需变形顶点有预期权重组；没有孤点/非有限值，权重非负且按目标策略归一化；影响骨数量和 LOD 指标符合实际预算 |
| 变形校正 | 对肩胯挤压、肘膝折叠、手腕扭转、面部/附肢或道具接触等已识别风险，按需要使用辅助骨、修正形态、驱动或姿势空间修正。BlendShape 几何归建模；绑定只连接并驱动已交接目标 | 校正项有命名、触发范围与依赖说明；未改变原始 BlendShape 目标几何、槽位、UV 或顶点顺序 |
| 压力姿势与挂点 | 覆盖最大关节活动、扭转、交叉/遮挡、接触、蹲伏/伸展、道具握持、挂点变换及实际动作要求。对挂点检查局部轴、父骨、Pivot 和导出保留性 | 有代表姿势清单与技术检查结果；显示问题输出截图/片段和检查要点供用户人工检查，不自动分析或代用户确认 |
| LOD 蒙皮 | 在各 LOD 上核对网格与骨架关联、顶点组/权重迁移、关节轮廓、辅助骨、挂点与校正需求；不同拓扑不能假设逐顶点一致，采用经验证的转移方法后逐级检查 | 每个 LOD 权重、骨骼数、变形压力姿势和目标预算有独立记录；切换不会丢失必要节点或产生异常变形 |
| 保存、导出与回读 | 保存可编辑源和依赖；在派生副本中明示对象集合、Armature、目标骨骼、FBX 轴向、单位、变换、蒙皮/形态选项和实际导出参数。排除控制器、参考、相机、灯光和无关网格；按[Unity 导入流程](../../unity-development-workflow/references/3d-character-unity-import.md)保留必需根、祖先和挂点 | 各 LOD FBX 独立回读，骨骼/网格/权重、Pivot/轴向/比例、形态通道与槽位映射可核实；源未被破坏且产物可重开 |

### 权重与变形验收

- 权重检查至少覆盖顶点权重为空、只含零值、负值或非有限值、归一化误差、每顶点影响骨数超预算、无效/重复组名、权重引用非预期骨以及 LOD 对应缺失。超限规则按真实导入器和目标平台决定并记录，不从通用惯例臆定。
- 从绑定工作台的压力姿势，以及已有且获准使用的代表动作中选取覆盖姿势，检查变形骨骼处的捏陷、爆点、扭转体积、皮肤滑移、穿插、自交、脚底/手部接触和挂点偏移。若动作尚未制作，使用具名极限/接触姿势验证，不在绑定阶段代制正式动作；技术读数之外的外观由用户检查实际截图或播放片段。
- 发现缺陷按所有权退回：几何/拓扑/BlendShape 目标几何回建模，贴图与材质信息回模型/纹理负责人，骨架/蒙皮/约束回绑定。上游更新后按受影响的 LOD 权重、校正与导出依赖重验。

## 导出门槛与交付

- 运行时变形骨、root、必要祖先链和挂点按[Unity 导入合同](../../unity-development-workflow/references/3d-character-unity-import.md#导出职责与统一基准)显式保留；不可只勾“仅变形骨”后假设无权重 root、祖先或道具挂点仍会导出。明确 FBX 对象与骨骼集合，并确认控制骨未污染运行时层级。
- 导出在派生副本执行，源 `.blend`、外链资源、烘焙结果、配方、实际路径与许可可重开并可追溯。FBX 逐个回读，不凭导出成功即判定通过。
- 移交动画负责人骨架源版本、root/静置姿势、变形骨命名/局部轴、控制与约束烘焙关系、动作相关校正、面部通道、LOD 对应、挂点和已知限制。骨架结构变更通知动画负责人并重验已绑定/已动画资源。
- 交 Unity 角色导入流程处理 Avatar/Generic 或 Humanoid 识别、SkinnedMeshRenderer、权重限制、Prefab 与导入播放核验。绑定自检、专业审查和 Unity 技术结果均不代替用户显示确认；V3 交付资源级 Prefab，正式场景和 gameplay 验收留在 V4。
- 3D 角色不套用 2D 专用 `riggingDelivery` 或 `uwt_validate_2d_rigging`；沿用现有 Work Item、Evidence 和适用的项目 3D 验证能力，不新建状态或 Schema。

交付缺少版本、源依赖、权重报告、压力姿势证据、LOD 对应或 FBX 回读之一时，明确列为 `BLOCKED`/待验，不能宣称生产 Rig 就绪。
