# P3-002 Unity 2D 骨骼系统

## 何时读取

在静态角色视觉通过后、制作 Rig、Sprite Skin、IK、Animator、判定框、换装挂点或性能预算前读取。只返修单个动作曲线时，同时读取[关键姿势骨骼动画](player-character-skeletal-animation.md)。

## 输入

- 读取获批的 17 张独立 PNG、几何与遮挡合同、SpriteLibrary、SpriteAtlas 和 PlayerCharacter Prefab。
- 读取当前 Unity 项目包清单、目标平台、角色移动与物理实现、动作清单、装备与换装范围。
- 读取 30 骨骼层级、局部轴、关节 Pivot、网格、权重、排序、Animator、IK、碰撞体和性能证据。
- 使用 `templates/player-character-2d-skeletal-system.yaml` 建立系统规格，并用对应 Schema 和验证器校验。

## 执行步骤

1. **选择生产路线**：比较刚性部件拼接、Sprite Skin 网格变形和外部骨骼工具导入。P3-002 固定采用独立 PNG、Unity 2D Animation、Sprite Skin 与 Animator 的混合路线；记录选择原因，禁止临时混入不共享骨架、坐标和资源标识的替代路线。
2. **冻结骨架合同**：冻结根骨、视觉根、翻转根、30 骨骼父子关系、关节 Pivot、局部轴、效应器和挂点骨。只保留能改变轮廓、变形、约束或附件的骨骼；Rig 版本变化时失效权重、IK、Clip 和判定跟随证据。
3. **冻结图片与排序**：让全部 Sprite 共享 PPU、Pivot、参考姿势和局部坐标。使用 Sorting Group 和明确排序带处理后发、身体、裤、鞋、上衣、前发、五官、配饰及武器前后切换；禁止通过临时 Z 偏移修补遮挡。
4. **制作网格和权重**：按肩、肘、髋、膝等变形热点配置足够顶点，在刚性五官、鞋和配饰上保持稀疏或刚性权重。限制每顶点骨骼影响数、单层顶点数和角色总顶点数；用极端姿势检查塌陷、裂缝、拉丝和轮廓尖角。
5. **建立 IK 与约束**：先播放基础 Clip，再按 `BASE_CLIP`、`RUNTIME_IK`、`SECONDARY_MOTION` 顺序求解。为脚贴地、头部朝向、手部目标和双手持物声明链长、弯曲方向、混合时间和超距策略；禁止 IK 瞬间切换或强拉超过骨架长度。
6. **建立动画控制**：按待机、移动、跳跃、攻击、受击、死亡、技能和交互划分状态；用 Blend Tree 或等价连续混合处理速度与方向，用分层遮罩处理上半身动作。逐类声明进入、退出、打断和相位同步，禁止所有状态共用同一过渡时间。
7. **校准位移和步幅**：让 Rigidbody2D 或玩法代码拥有角色真实位置，保持根运动关闭。使用“步幅 ÷ 循环时长 = 期望速度”校准移动动画，并在走跑切换时同步支撑脚相位；超出滑移预算时调整动画速度、步幅或玩法速度。
8. **处理左右朝向**：只翻转独立视觉根，不缩放物理根、碰撞根或玩法挂点。翻转后重新绑定 IK 目标与肘膝弯曲方向；非对称服装、发型、武器和文字使用专用变体，不假设镜像后仍然正确。
9. **同步玩法事件**：把攻击判定、投射物、连击窗口、无敌帧和动作完成交给结构化玩法动作规格；只让动画事件承担脚步声、表情、粒子等表现提示。任何关键玩法事件都要绑定动作 ID、时间窗口和可回归证据。
10. **分离物理与视觉**：让 Rigidbody2D 和主碰撞体驱动角色根，让骨骼驱动视觉与只读跟随点；在固定更新、动画求值和 LateUpdate 约束之间声明唯一更新顺序。攻击框、受击框和交互点只跟随批准骨骼，不让物理与 Animator 同时写同一 Transform。
11. **建立换装和附件**：复用同一骨架、参考姿势、画布、Pivot、网格规范和排序策略；为主手、头部、背部、项链和耳环建立稳定挂点与局部姿势证据。换装后重新检查身体泄漏、接缝、遮挡、极端姿势和 GUID 稳定性。
12. **建立性能预算**：限制每角色骨骼、蒙皮顶点、约束和跟随碰撞体数量；合并图集和材质，离屏暂停或降频更新，为远处角色使用简化 LOD。只用目标设备 Profiler 证据批准预算，禁止根据编辑器流畅度推断移动端通过。
13. **执行系统回归**：依次验证参考姿势、极端变形、排序切换、脚贴地、双手持物、状态混合、步幅、翻转、玩法事件、物理跟随、换装和性能。系统规格通过后，单个动作再进入关键姿势和动态质量流程。

## 子代理角色与并行边界

- 允许只读审阅骨架、排序、权重、Animator、物理和性能证据并行；同一 Prefab、Rig、Sprite Skin、Animator Controller 和碰撞体保持单写。
- 让动画设计者负责状态、姿势和节奏，让技术动画负责 Rig、权重和 IK，让玩法开发负责位移、事件与物理，让 QA 负责翻转、换装和目标设备性能。
- 任一骨架、Pivot、排序带或挂点变化时，停止受影响的动画、物理、换装和性能审阅并重建证据。

## 所需锁与 Unity 权限

- 审计现有资产时只使用只读权限；修改前绑定唯一 Unity MCP 实例。
- 写入前取得 PlayerCharacter Prefab、Sprite Skin、骨架、Animator Controller、AnimationClip、2D IK、Sorting Group、碰撞体、SpriteLibrary、SpriteAtlas 和 AssetDatabase 独占锁。
- Editor 编译、导入、域重载、PlayMode 或 Prefab Stage 脏状态时禁止写入；验证前优先复用现有 Unity 进程，不启动重复实例。

## 机器可读输出

输出符合 `player-character-2d-skeletal-system.schema.json` 的 YAML/JSON，建议路径为 `Artifacts/Animation/P3-002/Rig/<version>/skeletal-system.yaml`。记录生产路线、骨架、排序、蒙皮、IK、动画控制、朝向、玩法事件、物理、附件、性能和证据绑定。运行：

```powershell
node scripts/validate_player_character_skeletal_system.mjs --source Artifacts/Animation/P3-002/Rig/player-rig-v1/skeletal-system.yaml
```

让每个 AnimationClip 规格通过 `skeletalSystemVersion` 和 `skeletalSystemEvidence` 绑定该系统版本。脚本只证明结构和可计算约束，不替代视觉、手感或性能人工判断。

## 通过条件

- 固定统一生产路线、30 骨骼、参考姿势、Pivot、排序带、网格预算和权重证据。
- 让脚、手和头部约束具备链长、弯曲方向、超距处理和连续混合；保持求解顺序稳定。
- 让状态分层、过渡、打断、脚相位和步幅速度校准与玩法一致；保持根运动关闭。
- 让翻转只作用于视觉根，关键玩法事件不依赖动画事件，物理根不被骨骼或 Animator 写入。
- 让换装与附件复用骨架和挂点，并通过遮挡、接缝、极端姿势和 GUID 检查。
- 让骨骼、顶点、约束、跟随碰撞体、离屏更新和 LOD 满足目标设备预算并绑定 Profiler 证据。
- 完整通过参考姿势、变形、排序、IK、状态、位移、翻转、事件、物理、换装和性能回归。

## 失败与恢复出口

- 路线、参考姿势或坐标不统一：返回生产路线与骨架合同，禁止继续制作 Clip。
- 遮挡错误：修正排序带或动态规则；禁止使用临时 Z 偏移或逐动作特例。
- 关节塌陷、裂缝或拉丝：返回网格与权重，不通过增加骨骼旋转掩盖。
- IK 翻转、超距或跳变：修正链、弯曲方向、目标范围和混合，再重做相关动作证据。
- 滑步或状态跳变：重新校准步幅、循环速度、脚相位和逐类过渡。
- 翻转破坏物理、挂点或非对称视觉：分离视觉根并建立专用变体。
- 玩法判定漂移：把关键事件返回玩法动作规格并重建判定窗口，禁止依赖零散 AnimationEvent。
- 性能超预算：先减少非关键骨骼、顶点、约束和更新频率，再考虑牺牲画面；重新采集目标设备证据。
