# P3-002 关键姿势骨骼动画

## 何时读取

17 张玩家角色单图、完整组合和 Unity 原生 SpriteRenderer 视觉验收全部通过后，制作或返修 P3-002 的 Unity 2D 骨骼动画时读取。静态视觉尚未通过时保持 30 骨骼、Sprite Skin、权重和动画暂停。

## 输入

- 读取已通过 `player-character-2d-skeletal-system.schema.json` 校验的当前骨骼系统规格，并绑定 `skeletalSystemVersion` 与 `skeletalSystemEvidence`。
- 读取当前获批的 17 张 PNG、PlayerCharacter Prefab、30 骨骼层级、Sprite Skin、网格和权重版本。
- 读取骨骼局部轴校准证据、角色根节点坐标系、固定验收相机和地面基线。
- 读取动作意图、动作类型、移动控制权、4～8 张关键姿势卡、世界空间目标、接触约束、变形预算和视觉事件。
- 读取当前来源修订、项目状态版本、静态姿势批准截图及现有 Animator 接入策略。

禁止把“上臂旋转 +62°”一类局部角度作为动作设计输入。先冻结最终画面和身体力学，再让 Unity 中求得的骨骼曲线服务于画面。

按以下优先级处理质量：`KEY_POSE`、`TIMING`、`TRAJECTORY`、`SECONDARY_MOTION`。关键姿势和节奏未通过前，禁止用更多关键帧、曲线平滑、拖影或头发摆动掩盖问题。

## 执行步骤

1. **绑定骨骼系统**：记录骨骼系统规格、Prefab、Rig 版本、30 骨骼、根骨、头/手/脚效应器和局部轴校准证据。系统版本、Rig、网格、权重、骨骼层级或轴校准变化时，使全部姿势解、AnimationClip 和动态审查证据失效。
2. **冻结动态质量合同**：使用 `motionQuality` 声明动作风格、IK 单帧最大权重变化、关节最大伸展比例、蓄力与爆发段及其最大时长比，并固定 1 倍速和 0.25 倍速审查。
3. **编写动作意图和关键姿势**：拆成 4～8 张姿势，优先表达 `NEUTRAL`、`ANTICIPATION`、`EXPLOSION`、`IMPACT`、`CELEBRATION`、`HOLD`、`RECOVERY`。为每张姿势写可读轮廓、重心、承重点、动作线和重量意图。
4. **冻结世界空间目标**：在 `CHARACTER_ROOT_WORLD` 中记录头、双手和双脚目标及容差；只为肘、膝记录弯曲方向和最低弯曲程度。需要够远处目标时先移动骨盆或胸腔，禁止锁死关节或缩放手脚。
5. **冻结接触约束**：脚为 `PLANTED` 时记录世界空间锚点和最大滑移；连续固定期间保持锚点和脚部 IK。离地时显式改为 `RELEASED` 或 `AIRBORNE`，并使用连续权重曲线切换 IK，禁止单帧跳变。
6. **声明变形预算**：记录肩部旋转上限、肘部范围、裤腿张开距离、头发摆幅、手脚缩放许可、刚性图层和网格返修触发条件。姿势为 `MESH_REVISION_REQUIRED` 或 `BLOCKED` 时先修网格或权重。
7. **逐张摆静态姿势**：在 Unity 中只摆当前姿势，验证重心与承重点、脚底、肘膝方向、轮廓、遮挡和蒙皮。保存 `resolvedPoseEvidence` 和固定相机 `acceptanceScreenshot`；全部达到 `STATIC_POSE_PASS` 后再请求姿势卡批准。
8. **制作时间脚本**：为相邻姿势建立唯一时间段，声明阶段、速度曲线、五个效应器的轨迹类型、传力链、错位跟随和双脚 IK 混合。让骨盆和躯干驱动有重量的爆发动作，让手、头发、衣物依次延迟停止；禁止所有骨骼同时启停。
9. **建立节奏反差**：让蓄力段早于爆发段，并使爆发时长不超过声明的蓄力比例。为强调点保留明确姿势或短保持，再进入缓冲和恢复；禁止把所有曲线都设成同一种平滑缓动。
10. **声明运行时接入**：在 `runtimeIntegration` 中固定动作类型、角色位移控制权、进入/退出过渡、打断策略和循环相位同步。保持玩法或 Rigidbody2D 控制真实位置；移动循环必须同步脚部接触相位，单次动作不得用过长混合削弱爆发。
11. **生成 AnimationClip**：只消费已批准姿势的 `resolvedPoseEvidence`、时间脚本和当前轴校准，生成版本化 `.anim`。防止曲线过冲、手脚轨迹折返和关节锁死；不得覆盖旧 Clip，不得把局部角度数组散落在 C#。
12. **添加视觉和次级运动**：主体动态通过后再添加表情、颜色、高亮、闪白、拖影、头发和服装跟随。让次级运动服从已声明的传力顺序和变形预算，禁止用视觉事件遮盖姿势、节奏或蒙皮错误。
13. **执行动态审查**：以 1 倍速检查操作反馈、节奏和张力，以 0.25 倍速检查速度断点、轨迹尖角、IK 跳变、脚滑和次级运动顺序；输出头、双手和双脚轨迹证据，并逐段填写 `speedContinuity`、`trajectory`、`ikContinuity`、`bodyMechanics` 和 `tension`。
14. **执行固定时间回归**：在每个关键姿势时间点自动截图并与批准图 A/B；同时检查脚滑、目标误差、轮廓、肘膝方向、肩袖、裤裆、头发和刚性图层。静态回归与动态审查全部通过后再请求最终批准。

胜利动作示例位于 `templates/player-character-skeletal-animation.yaml`，结构由 `schemas/player-character-skeletal-animation.schema.json` 约束。核心原则是：画面定义姿势，身体力学定义重量，动作脚本定义节奏和轨迹，接触与 IK 定义稳定性，Unity 曲线只负责实现。

## 子代理角色与并行边界

- 允许动画设计者准备动作意图、轮廓、身体力学和姿势卡；要求同一 Rig 的静态姿势求解、权重修改和 AnimationClip 写入保持单写。
- 让视觉一致性审阅者检查轮廓、表情和视觉事件；让 Unity 可实现性审阅者检查 Rig、目标误差、接触、IK 和曲线；让 UX/可读性审阅者检查节奏、张力和移动端辨识度。
- 允许静态姿势、变形和只读轨迹审阅并行；任何网格或权重修改都要停止审阅，并让受影响姿势返回静态求解。

## 所需锁与 Unity 权限

- 读取 Rig、轴校准、Sprite Skin、网格、权重、Animator 和现有 Clip 时只使用只读权限。
- 摆姿势、修改网格或权重、生成 Clip、写 Animator 前，显式绑定唯一 Unity MCP 实例并取得 PlayerCharacter Prefab、Sprite Library、Sprite Skin、AnimationClip、Animator 与 AssetDatabase 独占锁。
- 构建期间禁止其他写入者修改 Rig、骨骼层级、轴校准、Sprite GUID、网格或权重；Editor 编译、导入、域重载、PlayMode 或 Prefab Stage 脏状态时禁止写入。

## 机器可读输出

输出符合 `player-character-skeletal-animation.schema.json` 的 YAML/JSON，建议路径为 `Artifacts/Animation/P3-002/<Animation>/<version>/animation-spec.yaml`。至少记录：

- `rigBinding`：当前骨骼系统版本、系统证据、Rig、效应器和轴校准。
- `motionQuality`：质量优先级、风格、IK 权重变化、关节伸展、节奏反差和审查倍率。
- `runtimeIntegration`：动作类型、移动控制权、状态过渡、打断策略和相位同步。
- `keyPoses`：意图、轮廓、重心、承重点、动作线、世界目标、接触、关节形状、视觉状态、变形结论和静态证据。
- `timeScript`：阶段、起止姿势和时间、曲线、保持、轨迹计划、传力链、错位时间和 IK 混合。
- `motionReview`：1 倍速、0.25 倍速、轨迹报告及全部时间段的动态质量结论。
- `regression`、构建结果和批准：绑定同一动画 ID、版本、Rig、来源修订和固定相机证据。

运行：

```powershell
node scripts/validate_player_character_animation.mjs --source Artifacts/Animation/P3-002/Victory/victory-v1/animation-spec.yaml
```

脚本只证明结构、时间、约束和证据链一致，不会自动宣布动作自然或视觉正确。

## 通过条件

- 保持 4～8 张关键姿势，确保 ID 唯一、时间严格递增、第一张位于 0 秒、最后一张不超过动画时长。
- 绑定已审计的当前骨骼系统版本；骨架、排序、蒙皮、IK、Animator、位移、翻转、事件、物理、附件或性能变化时重新审计受影响动作。
- 确保剪影能单独表达动作，重心、承重点和接触状态一致，爆发动作从骨盆向躯干和四肢传力。
- 逐段连接相邻姿势，确保蓄力早于爆发并满足时长比例；保留爆发、强调、缓冲和恢复之间的速度反差。
- 让头和手按声明弧线运动，让固定脚使用 `LOCKED` 轨迹；不得出现尖角、折返、脚滑或未声明的速度断点。
- 限制 IK 单帧权重变化，保持固定脚端点权重不低于 0.95；保持关节微弯并遵守最大伸展比例。
- 让运行时位移、进入/退出过渡、打断策略和循环相位与玩法一致，避免碰撞体、角色位置和画面分离。
- 在姿势卡批准前，为每张姿势提供 `STATIC_POSE_PASS`、验收截图和已求解姿势证据；确保全部姿势在变形预算内。
- 在最终批准前，让全部关键时间点回归、1 倍速、0.25 倍速、轨迹报告和逐段动态质量检查均为 `PASS`。
- 只从批准的结构化规格生成 AnimationClip，禁止散落硬编码局部角度数组。

## 失败与恢复出口

- 姿势不可读、重心或承重点错误：返回关键姿势设计，禁止通过增加过渡帧修补。
- 蓄力与爆发时长接近、动作软弱：重写时间脚本和强调点，再重做后续曲线和动态证据。
- 世界目标不可达、关节锁死或传力顺序错误：调整骨盆、胸腔、目标或传力链；保持当前姿势或时间段失败。
- 轨迹尖角、速度断点、IK 跳变或脚滑：修正轨迹、曲线、接触状态和 IK 混合，并重录 0.25 倍速与轨迹证据。
- 轮廓、肩袖、裤裆、头发或刚性图层超预算：返回网格或权重阶段；新版本使全部受影响姿势和下游 Clip 失效。
- Rig 局部轴、骨骼层级、Sprite GUID、网格或权重变化：重新校准轴并从第一张静态姿势开始。
- 姿势时间、运行时过渡或内容变化：重建受影响段落、视觉事件、动态审查和对应回归截图。
- 无法证明动态证据来自精确版本、固定相机和声明播放倍率：保持 `PLAYER_CHARACTER_ANIMATION_REGRESSION_REVIEWING` 或 `PLAYER_CHARACTER_ANIMATION_BLOCKED`，禁止批准。
