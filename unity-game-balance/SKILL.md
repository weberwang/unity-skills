# Unity 游戏数值设计

把体验目标转为可解释、可调整、可验证的模型，不以未记录的主观调参替代证据。

## 输入与决策

读取 Work Item、相关玩法、配置、测试、GDD 和 `docs/balance.md`。目标节奏、经济、商业化影响、允许偏差、验收阈值或高风险曲线存在实质取舍时交给 `$unity-game-grilling`；其余范围内可逆配置由实施包记录后推进。

## 执行与交接

1. 定义玩家节奏、成功率、资源来源/消耗、失败成本、保底、上下限与异常行为。
2. 在 `balance.md` 记录参数、单位、默认值、来源、公式、敏感度、影响和验证方式；运行时通过集中、可版本化配置读取。
3. 为关键曲线保存可复现计算、模拟种子、样本规模与试玩记录；不要把表格结果当作游戏内验证。
4. 向玩法提供配置、边界和验收样例，向 QA 提供统计口径、容差与高风险场景。
5. 变更参数时标记受影响场景、存档、测试和性能结论，并触发必要复验。
