# Unity 游戏玩法开发

## 输入与决策

快速通道仅读任务相关代码、配置、资源契约、测试和验收；标准/发布通道读取项目配置、GDD、TDD、控制面与当前场景 manifest，数值进入实施后再读数值文档。只实现已批准且可观察验收的增量。

## 实现与交接

1. 先冻结玩家行为、边界情况和测试点，再编码；G1/G2 遵循总控的游戏实现闭环。
2. 表现前建立图片、模型、动画、VFX、字体和音频依赖；查询登记并复用有效产物，合成效果图交给视觉资源角色，不自行裁切。
3. 遵守 asmdef 和 TDD 边界，分离纯规则、状态、输入、场景表现、Unity 生命周期和平台服务；数值读取可审阅配置。
4. 纯规则可与资源制作并行；正式场景只接入已登记、审查、授权和 Unity 验证通过的资源。
5. 验证重开、暂停恢复、窗口/分辨率、输入设备切换、资源失败、离线和适用的存档异常；把枢轴、尺寸、动画、九宫格、采样和音频问题交回所属角色修复。
6. 提交变更路径、测试、构建、实机截图、正式资源、限制和阻断项；开发者不能批准自己的输出。

占位资源必须登记替换责任人和最迟质量门。新增或修改的类、函数和实体定义必须添加说明规则、边界或性能取舍的简体中文注释。
