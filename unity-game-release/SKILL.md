# Unity 多平台发布与合规

准备可交付候选包不等于已经签名、上传、发布或通过外部审核。账号、证书、令牌、崩溃数据和个人信息只进入受控外部系统。

## 输入与决策

读取项目配置、GDD、TDD、控制面、发行矩阵、资源/音频登记、QA 计划、G2 逐模块与逐平台验收结果和发布清单。发行渠道、数据处理、第三方 SDK、商店资料、设备档位、已知风险接受、回滚策略和最终放行需先交给 `$unity-game-grilling` 逐项确认，生成绑定当前候选包的批准记录；缺少当前版本记录时不得签名、上传或发布。

## 执行与交接

1. 核对用户批准的平台集合和每个平台的 Unity 6 Build Profile、脚本后端、版本、场景、图形 API、输入、屏幕策略与日志配置；未选择平台不得生成候选包。
2. 先深验 G2 已覆盖当前拆分中的全部模块、场景和用户批准平台；任一模块或平台报告缺失、重复、失败或失效时，不得生成最终候选包或开始设备验收。
3. 只从可追溯源码修订和可复现构建配置生成各平台候选包。Windows/Android 优先使用可用的 `manage_build`；iOS/iPadOS 必须在 macOS/Xcode、签名和真机条件具备时生成 IPA，否则保持 `BLOCKED`。
4. 对每个平台候选主制品执行“对应设备档位 × 全部批准场景”最终矩阵，逐项核对启动、核心循环、输入、屏幕适配、音频和稳定性；缺平台、缺设备类型、缺场景或混用构建时不得通过。
5. 核对资源、字体、音乐、第三方包与生成内容的权属/许可，记录隐私、联网、遥测、崩溃收集、账号和商业能力实际状态。
6. 按发行方式准备图标、截图、描述、分级、安装/卸载、系统要求、发布说明、已知问题和回滚方案。
7. 由独立角色核对制品与证据；没有用户明确放行时不得声称已准备上架，更不得签名、上传、覆盖稳定制品或创建外部发布。

输出候选包、`delivery-manifest.yaml`、`quality-report-device-acceptance.yaml`、发行清单和风险摘要；把外部提交与审核状态如实标记为未执行、进行中或实际结果。
