# Unity 资源管线

在场景 V2 已冻结拆解与生产边界、准备进入 V3 资源生产和组合验收时读取。

## 前置

每个资源项绑定 Work Item、场景/组件/状态、目标节点、来源、许可、规格、目标项目路径和验证方式。静态特色外观必须先确认独立生产资产；文本、动态数据、布局、基础几何、进度、粒子或 Shader 才能进入 `UNITY_NATIVE`，并持有资格证据。存在视觉、授权、外部上传或付费取舍时必须有当前 `USER_DECISION`；普通本地创作和导入不创建多余批准。

消费 V2 的[文本与色彩拆分结果](visual-decomposition-routes.md)：系统文本、原生填充也须有编号、实施责任与消费节点；低显著性项可按已确认方案使用原生能力，明显美术文字、材质、纹理和光影按独立资产生产或复用。字体/贴图/材质依赖保留真实来源，原生组件加载资产不等于程序生成其外观；原生项与图片项共同参加 V3 组合覆盖检查。

公共资源执行[登记与使用规则](shared-asset-usage.md)：复用前查项目唯一总表，生产者提交独立事实，指定单写者在当前资源交接时合并登记；实际消费关系保存在各场景/显示层拆解和装配合同，同一资源只登记一次，不为每个使用点复制资产。

## 生产与导入

按[图片优先的确认方式](../../unity-game-workflow-control/references/simplified-workflow.md#图片优先的确认方式)内部维护制作分析与提示词，在已确认范围内直接制作并展示真实候选。静态图片以画廊或可放大对照交付，透明资源提供深浅底预览；依赖父图的动画仍按实际素材确认推进。同目标返修直接展示前后结果，不额外等待文字修复方案。

原子资源继承冻结目标中的[玩家可见表达](game-copy.md)，不从内部规格添加说明，也不借精简规则删改冻结文字；动态数值和本地化文本保持独立文本节点。候选生产、导入工程结果与用户显示确认分别记录。

1. 枚举 V2 全部资源项，确保每项只有一个生产通道和至少一个消费节点。
2. `REUSE` 核对实际源路径、精确 Unity GUID、许可、已确认视觉要求、实际 Importer 设置、消费节点和相关 Unity 验证；资源引用错误、授权不足或实际质量不满足时修复，不校验源 SHA 或设置摘要。
3. 独立生产位图、模型、材质、字体、音频或 VFX。UI/2D 位图默认以 `sourceScale=1` 生产，批准的平台预算或像素美术合同可覆盖该值。禁止从高保真效果图裁切、抠取、放大或轻微修饰成运行资源，禁止整图铺底或把整屏截图作为单区域来源。
4. 导入前校验唯一 Unity 实例、Editor 稳定、目标路径和单写者；资源与 `.meta` 归同一单元，禁止猜测或手写 GUID。
5. 通过 AssetDatabase/对应 Importer 导入并设置平台参数；移动或重命名资源使用 Unity API，避免引用断裂。
6. 域重载和导入稳定后，复读 GUID、Importer、序列化引用、Addressables/资源登记与 Console；运行最小 EditMode/PlayMode 或隔离 Prefab 验证。
7. 在宿主 Scene/Prefab/UXML 中完成 V3 同屏组合验收；缺项、孤儿资源、占位、旧版本或未验证引用均阻塞。装配必须绑定 `parentElementId`、`semanticGrouping` 和 `layoutBinding`，不能只凭几何相似证明结构。

SpriteAtlas、压缩、MipMap、Read/Write、色彩空间和 Addressables 由 Unity 平台预算决定，不照搬 Web DPR、Canvas 或统一禁止图集规则。
