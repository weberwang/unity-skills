# 场景 V0-V4 闭环

## V0 分流

确定场景 ID、宿主 Scene、模块依赖、显示层清单、视觉模式、平台约束和验收轨迹。纯工程模块不伪装成场景；跨场景入口归 INTEGRATION。

## V1 场景定义

冻结玩家行为、状态、失败/恢复、输入、相机、UI、数据所有权与 Scene/Prefab/UXML 结构。草图和灰盒只能承载布局与交互验证，不注册为正式资源。

## V2 拆解确认

冻结组件×状态、布局父子关系、生产路线、资源/Importer/GUID/Addressables 约定、显示层上下文和验收条件。只有真实取舍才请求用户决定；已确认事实不重复询问。

## V3 资源与组合验收

全部必需正式资源在 Unity 中导入并验证，宿主 Scene/Prefab/UI 组合没有缺失引用、孤儿资源、占位或 Console 错误。显示层可作为子任务并行准备，但必须持有自己的 V2/V3 证据和互斥所有权。

## V4 正式实现与运行验收

正式实现绑定当前 V2/V3，完成玩法、视觉、音频、输入、生命周期和清理；在 Editor/PlayMode 中重放关键轨迹，保存当前候选的结构、测试、截图和性能证据。所有必需显示层关闭后才报告场景完成。

不同场景可并行只读准备；正式 Unity Editor 写入受单写者约束。完成一个场景不是切换下一个场景的强制前提，只有共享资源、入口或状态所有权存在依赖时才串行。
