# 场景小循环

## 何时读取

实现或修改任一 Scene、Prefab、UI 页面或显著视觉状态时读取；一次只允许一个主场景进入正式 Unity 验收。

## 固定顺序

1. 核对 G0 范围、冻结 Visual Bible、场景 ID、平台和验收；缺一即停止。
2. **A1 草图/灰盒**：制作实际可查看的草图或灰盒草图，并提交稳定节点、层级、布局、交互、状态和资源槽说明；F0-F3 后请求 F4 确认。
3. **A2 高保真**：只基于已确认 A1 与 Visual Bible 生成；完成实际预检和非作者专业审查，F3 收敛后请求 F4 确认当前精确版本。
4. **A3 资产地图**：只分析已确认高保真原图，直接在效果图上为每个元素框选并标注“序号 + 路线 + 简要说明”（例如 `[01][GENERATE] 竞技场背景`）；每项必须包含 annotated split preview 中的对应范围、`bounds`、`targetSize`、透明、Pivot、PPU、Border、状态变体、目标节点/路径和复用/排除理由。缺标、错号、框选越界或说明缺失不得送审。F4 必须由用户确认该精确拆解版本，并留下 `USER`/`ASSET_MAP` 批准及 ID、版本、证据路径和 SHA-256 绑定；批准前禁止正式生成、导入或写入 Scene/Prefab/UI，代理、脚本、哈希或含糊“继续”不能代批。确认后才逐项独立生产、导入和验证需要的单图及其他元素。`REUSE` 项必须填写完整 `reuseResourcePlan` 并在复用前核对源哈希、许可、风格、Importer 设置和最近 Unity 验证；其中 `effectImagePixelReuse: FORBIDDEN` 只禁止从高保真效果图取像素，按 `sourcePath`/`sourceSha256` 复用已登记源资源是允许的；禁止把裁切、改色或修饰效果图标记为复用。`PROGRAMMATIC`、`CODE`、`MATERIAL`、`VFX` 和 `MODEL_3D` 走 Unity 图元/UXML/USS、Shader、代码或对应结构化责任通道，不创建图片生成任务。拆解项增删、合并、分类、尺寸、边界、节点映射或源高保真身份变化都使批准和下游产物失效并需重审。禁止裁切效果图或整图铺底。
5. **A4 结构化还原**：以 Scene/Prefab/UXML/USS 等真实结构接入，通过 Unity MCP/C# Toolkit 验证层级、映射、布局、交互和 Console。
6. 删除草图、灰盒、占位和临时低保真对象，清理所有运行时与登记残留引用；清理验证实际 `PASS` 后才能冻结场景。
7. 完成玩法、音频、自动测试、性能静态预算、无设备平台适配和独立场景验收报告，再纳入 G2 汇总。

场景高保真不是全局三选一：可由 F2/F3 收敛成唯一推荐，但必须在专业审核完成后由 F4 确认当前精确版本。A1 草图确认、A2 高保真确认和 A3 资产地图确认互不替代；A3 的人工批准也不能由 A2 高保真批准或脚本校验替代。

## Unity 边界

写入前显式绑定唯一项目实例并核对 Editor 稳定、上游批准、目标基线与单写者；写入后等待稳定，复读对象、场景、Console、资源登记和最小测试。研发阶段只使用 Editor/Game View 证据。

全部场景、模块、Editor 验证和无设备平台适配通过后，G2 `PASS` 才表示研发完成。G2 前禁止安装或启动 Standalone/Player、真机或等价设备；G3 也不得自动发起真机验收。

## 回退

A0 变化回 A1；A1 变化回 A2 前；A2 变化回 A3 前；A3 变化（含拆解项增删、合并、分类、尺寸、边界、节点映射或源高保真身份变化）先撤销当前用户批准，再重做受影响单项和 A4。需要灰盒时从审计证据重建，不在运行时保留回退副本。任何 `FAIL`、`BLOCKED`、`NOT_RUN`、旧版本确认或哈希不符均停止切换主场景。
