# 动画意图与反馈时间轴合同

本合同把玩法目的转为可制作、可接入和可验收的动作时间轴，供 V1/V2 场景拆解、V3 资源组合与 V4 动态验收使用。沿用现有 Work Item 和阶段确认；不建立动画资产状态机，也不要求先制作动画灰盒。

## 动画意图

对每个动作说明：

- **玩法目的**：动作表达何种状态、信息或结果；权威规则和触发者由玩法角色持有。
- **表现意图**：姿态、方向、运动曲线和层级如何帮助玩家理解；包括开始、关键姿势、完成、循环或中断条件。
- **时间约束**：动作总时长、关键事件检查点、循环与过渡要求，以及使用的时间来源。各动作独立设定时长、FPS 和事件位置，不因批量生产而强制等长或同步。
- **验收点**：在实际素材/Unity 预览中需要观察的姿势、节奏、连接区、可读性和可恢复状态。

V2 将动作时间轴及事件语义与拆解编号、消费方、资源负责人和 Animator/Clip 接口对应。角色动画事件可通知表现或玩法入口，但命中、伤害、位移规则和状态裁定由玩法负责，不能由视觉资产或动画自行定义。

## 内部设计与真实素材确认

动作分析、阶段表、时长、FPS、尺寸、时间映射与提示词由代理内部维护。在已有玩法合同、阶段前置和操作授权明确时直接制作真实视频、关键帧或 Unity 动画预览，不要求先确认文字时间轴；确实无法推导的玩法事件、时长或行为权限才询问，并只暂停受影响动作。实际预览确认不能由文字参数、静态图或工具成功代替。

序列帧路线使用视频时，先准备实际最终抽帧输入并交用户验收，通过后才能抽帧；输入内容或时间映射改变时重验实际输入。图片递归路线在首尾、必要关键帧与实际父图确认后制作依赖帧，最后展示完整真实序列验收。独立静态资源不套用父图依赖规则；Unity 骨骼路线沿用拆件图和真实代表动画的既有确认。所有路线最终在 Unity 按当前 Clip/接口检查实际播放。

合理参数、分辨率与批次在已授权工具和预算内直接确定，未知费用不得虚构；新增费用、超预算或外部上传仍遵循现有授权边界。同目标返修直接修复并展示前后预览，不增加文字返修方案审批，也不因取消文字确认跳过 V0–V4 前序阶段或专项素材确认。

## 按资产路线分配责任

| 路线 | 制作与交接责任 |
| --- | --- |
| 2D 序列帧 | `$unity-game-visual-assets` 明确逐帧、视频抽帧或其他来源，交付帧序列、帧率/时长、Pivot 与导入信息；玩法消费已验收 Clip 或播放接口。 |
| Unity 原生 2D 骨骼 | 由 [`$unity-game-2d-rigging`](../../unity-game-2d-rigging/SKILL.md) 负责骨架、蒙皮、动画 Clip、Animator 接口和角色 Prefab；视觉资产角色负责独立部件，玩法负责动作触发与规则。 |
| Spine | 现有 `$unity-game-spine-reskin` 仅在骨骼、网格、约束、动画固定时负责换皮。需要新动画或修改骨架/Clip 时，必须在 Work Item 明确指定动画生产者、资源版本、运行时导入责任和验收接口；不得把换皮 Skill 当作新动画生产者。 |
| 3D 动画 | 在 Work Item 明确动画资产生产者、模型/骨架版本、Clip、Avatar/绑定、事件及 Unity 导入责任。`$unity-game-3d-modeling` 和 `$unity-game-3d-texturing` 分别负责模型和贴图，不默认承担动画制作；未指定动画生产者时，动画项保持未分配，不能标成正式资源就绪。 |

不同路线的资源生产方式可以不同，时间轴、事件含义、消费接口和 V4 动态检查点应保持一致。需要外部动画服务、付费或上传时遵循现有精确授权规则。
