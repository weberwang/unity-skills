# 动画意图与反馈时间轴合同

本合同把玩法目的转为可制作、可接入和可验收的动作时间轴，供 V1/V2 场景拆解、V3 正式资源生产与导入、V4 场景接入和动态验收使用。V3 可生产资源级 Prefab 并提供组合预览；正式宿主 Scene/场景装配 Prefab/UI 实现与校准属于 V4。沿用现有 Work Item 和阶段确认；不建立动画资产状态机，也不要求先制作动画灰盒。

## 动画意图

对每个动作说明：

- **实际使用场景**：动作出现的场景、角色职责、相机视角与实际显示尺度、操作频率、移动速度及前后衔接状态；复用动作前核对这些条件是否适用。
- **玩法目的**：动作表达何种状态、信息或结果；权威规则和触发者由玩法角色持有。
- **表现意图**：姿态、方向、运动曲线和层级如何帮助玩家理解；包括开始、关键姿势、完成、循环或中断条件。
- **时间约束**：动作总时长、关键事件检查点、循环与过渡要求，以及使用的时间来源。各动作独立设定时长、FPS 和事件位置，不因批量生产而强制等长或同步。
- **验收点**：在实际素材/Unity 预览中需要观察的姿势、节奏、连接区、可读性和可恢复状态。

V2 将动作时间轴及事件语义与拆解编号、消费方、资源负责人和 Animator/Clip 接口对应。角色动画事件可通知表现或玩法入口，但命中、伤害、位移规则和状态裁定由玩法负责，不能由视觉资产或动画自行定义。

## 按使用场景设计骨骼动画

总控安排动画导演：简单动作由设计师兼任，涉及多角色、多段调度或跨类型素材协作的复杂表演安排独立导演，统筹表演意图、空间节奏和不同动画路线之间的配合。另指定独立动画质量负责人，在动作设计时提供项目标杆，在代表动画与批量接入时提出专业审查材料。2D 的骨骼、TA 与部件岗位按[2D 动画岗位协作](2d-animation-collaboration.md)安排；3D 的建模、贴图、绑定和动画按[角色共同交接](3d-character-handoff.md)分工，不默认分配 2D TA 或套用部件图合同。导演创意、质量审查、工程检查和用户视觉确认各自履责，创作者不自审，质量意见与工程结果不能替代用户确认。

Unity 原生 2D 骨骼路线在拆件和骨架制作前，由玩法与骨骼角色共同评审根节点、朝向、挂点、关键事件与位移归属。按实际使用场景安排准备、发力、接触、收势等适用阶段的比例、停留、加减速和过渡；阶段是否存在及其时长由动作目的决定，不套用固定动作模板。移动类动作的步频、步幅和落脚应匹配实际速度，操作类动作的响应与恢复应满足玩法窗口，环境或待机动作的循环应适合实际重复频率与观看时长。受击、转向、打断等只在项目需要时制作，并检查回到后续状态的连续性。

代表动画按实际风险选择，覆盖主要运动及最容易暴露部件连接、遮挡、道具挂点或接触问题的情境；简单待机不足以覆盖时补充必要姿势或片段，在既有代表动画确认中一并展示。按正常播放速度和实际场景尺度检查节奏与可读性，再提供连接区细节及慢放材料供用户人工检查；孤立 Clip 顺畅不能代替玩法接入后的运行验收。

原生 2D 骨骼动作设计时同时判断现有部件能否表达目标角度、轮廓、手势和变形。骨骼/网格变形不足时，由骨骼角色提出部件替换图或必要过渡图需求，关联具体动作、姿势和切换时机，交视觉资产角色组织生产，再接回真实 Unity 动画；不强行拉伸原图，也不要求逐帧补图。变体映射、切换驱动与确认范围沿用[制作与交接合同](../../unity-game-2d-rigging/references/production-contract.md)，不另设生产状态。切换的节奏与前后姿态应连续，动作中断或返回默认状态时须恢复正确部件；补图影响已确认代表动画时，展示更新预览并取得确认后再扩展依赖动作。

原生 2D 的无缝组合要求贯穿拆件、蒙皮和动画全程，详细制作与返修边界见[制作与交接合同](../../unity-game-2d-rigging/references/production-contract.md)。确认覆盖的视角、方向、动作范围与显示尺度内不得出现裂缝、露底、错位、双轮廓或明显接缝；不能靠缩小画面、改变目标机位或放宽容差掩盖缺陷。截图和实际播放片段交用户人工检查，代理不自动分析截图或据此宣告视觉通过。

3D 动画按[角色共同交接](3d-character-handoff.md)消费已绑定网格、骨架、形态通道和材质，在 Blender MCP 内制作动作并按[角色导入合同](3d-character-unity-import.md)验证曲线、Avatar、Root、挂点与材质。关节形体/拓扑或 BlendShape 目标几何不足退建模，骨架/蒙皮/控制器不足退绑定，表面缺陷退贴图；不得把 3D 缺陷转为 2D 替换图生产。动作轨迹、接触和节奏的通用要求适用，2D 拆件/变体与专用工具条款不适用；实际显示仍交用户人工检查。

## 动画方案与真实素材确认

动作分析、阶段表、时长、FPS、尺寸、时间映射与提示词由代理内部维护。正式素材生产前，导演或兼任导演的设计师先向用户说明设计理念与动作方案，至少覆盖目标感受、关键表演与姿态变化、空间路径、节奏依据、动画路线间的配合及验收重点；用户明确确认方案后才制作真实视频、关键帧或 Unity 动画。确认沿用当前工作项的用户消息和阶段记录，不增加动画状态机或新的全局阶段。无法推导的玩法事件、时长或行为权限仍只暂停受影响动作并提出具体问题。真实素材完成后仍须交用户人工检查实际表现；文字方案、静态图、专业审查和工具成功都不能替代素材验收。

序列帧路线使用视频时，先准备实际最终抽帧输入并交用户验收，通过后才能抽帧；输入内容或时间映射改变时重验实际输入。图片递归路线在首尾、必要关键帧与实际父图确认后制作依赖帧，最后展示完整真实序列验收。独立静态资源不套用父图依赖规则；Unity 原生 2D 骨骼路线沿用拆件图和真实代表动画的既有确认。所有路线最终在 Unity 按当前 Clip/接口检查实际播放。

合理参数、分辨率与批次在已授权工具和预算内直接确定，未知费用不得虚构；新增费用、超预算或外部上传仍遵循现有授权边界。同目标返修直接修复并展示前后预览，不增加文字返修方案审批，也不因取消文字确认跳过 V0–V4 前序阶段或专项素材确认。

## 按资产路线分配责任

| 路线 | 制作与交接责任 |
| --- | --- |
| 2D 序列帧 | `$unity-game-visual-assets` 明确逐帧、视频抽帧或其他来源，交付帧序列、帧率/时长、Pivot 与导入信息；玩法消费已验收 Clip 或播放接口。 |
| Unity 原生 2D 骨骼 | 由 [`$unity-game-2d-rigging`](../../unity-game-2d-rigging/SKILL.md) 负责骨架、蒙皮、动画 Clip、角色 Controller 内部参数/状态/过渡/中断和角色 Prefab；视觉资产角色负责独立部件，玩法通过接口驱动动作并拥有权威玩法状态与规则。 |
| Spine | 现有 `$unity-game-spine-reskin` 仅在骨骼、网格、约束、动画固定时负责换皮。需要新动画或修改骨架/Clip 时，必须在 Work Item 明确指定动画生产者、资源版本、运行时导入责任和验收接口；不得把换皮 Skill 当作新动画生产者。 |
| 3D 绑定与动画 | [`$unity-game-3d-rigging`](../../unity-game-3d-rigging/SKILL.md) 用 Blender MCP 负责骨架/蒙皮/控制 Rig 和角色模型导出；[`$unity-game-3d-animation`](../../unity-game-3d-animation/SKILL.md) 用 Blender MCP 负责动作、运行时骨架曲线烘焙与逐 Clip 导出。按[角色共同交接](3d-character-handoff.md)绑定模型/UV、贴图、骨架/权重、Root、Clip 和事件，按[导入合同](3d-character-unity-import.md)接入 Avatar、Animator 和角色 Prefab；Work Item 明确具体生产者与集成单写者，模型/贴图角色不接管绑定或动画。 |

不同路线的资源生产方式可以不同，时间轴、事件含义、消费接口和 V4 动态检查点应保持一致。需要外部动画服务、付费或上传时遵循现有精确授权规则。
