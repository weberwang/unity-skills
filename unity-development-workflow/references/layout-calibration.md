# Unity 原生布局校准

正式 Scene、Prefab、UXML/USS 实现与布局校准在 V4 进行，以用户确认的 V1 为持续视觉目标、以 V2 已确认拆解图和布局图为实现规格；V3 只验收正式资源和导入，可提供临时预览，不在正式对象上校准。默认按可用性验收，仍须保留 V1 的显著构图、轮廓、配色、材质、光影及层级；项目已声明的关键几何容差即使在 `usability` 模式也必须满足，没有声明容差时仅输出测量，不擅定阈值。只有用户要求整屏精确还原时才启用 `exact` 的完整矩阵，不新增通用像素相似度阈值。

布局取舍与差异归因内部记录，按[组合对照交付](visual-workflow.md#v4-正式实现与运行验收)展示 V1 与实际 Unity 组合及已知未还原项，供 V4 阶段确认，不增加文字调整方案确认；同目标返修补充前后对照。组合文本沿用[游戏内文案](game-copy.md)的玩家可见表达与当前文本节点，不能把布局注释或业务说明填进正式 Label/TMP 文本。

## 校准方法

1. 使用现有 Inspector、Rect 工具、UI Builder 和 Unity Undo 调整锚点、父子布局、边距与尺寸。保持已确认的场景/底板/屏幕参照和安全区，不新增 Web 编辑器。
2. 在同一个实际视口和布局参照下测量目标与交付的矩形、边距、间距及差值。Toolkit 命令 `uwt_measure_layout` 负责读取实际几何并输出测量结果，不自动改动布局，也不从截图推测矩形。
3. 如需给用户查看组合效果，使用 `uwt_capture_game_view` 采集 Unity Editor Game View。截图由用户人工检查；代理不自动分析截图或据此判定显示正确。
4. 保存 Unity 编辑结果并回读实际对象/布局值，然后提交 V4 实现交付及差值、采用的验收模式和未解决项，等待阶段确认。

`uwt_capture_game_view` 采用同一 Job 的请求与回查：首次返回 `PENDING` 只表示已登记请求，帧末真实图片与报告写入后才返回采集 `PASS`。仅在已有 Editor PlayMode、非 batch 且 Game View 可用时采集；不自动进入 PlayMode。退出 PlayMode、域重载或超时会取消当前请求。采集成功也不表示视觉验收通过。

## 差异归因

先按[追溯与检查边界](art-quality-contract.md#追溯与检查边界)区分拆解漏项、规格与目标矛盾、生成结果偏离规格、Unity 装配或适配偏差。前三类交回拆解或资源生产修复，不能一概当作布局问题。属于装配或适配时，再区分场景内容区域、屏幕安全区和弹窗底板内容区域，并定位实际所有者：

- 锚点、拉伸、层级、布局组或内边距错误：布局/装配负责人调整 Prefab、Scene 或 USS。
- Sprite 透明留白、Pivot、源图边框或纹理尺寸不符：资源负责人修正源资产或 Importer。
- 字体字宽、基线、自动换行或溢出不同：字体/文本负责人按字体与多语言合同修复。
- 仅在特定视口错位：响应式布局负责人检查 CanvasScaler、PanelSettings、场景区域换算和 resize 行为。

不得通过缩放、移动节点或提高容差掩盖缺失装饰、错误轮廓/颜色、透明区域或字体差异，也不得把截图视觉观感当作几何测量。无真实 Unity 测量的结论记录为 `NOT_RUN`；机器测量只证明几何事实，不代替用户确认显示效果。
