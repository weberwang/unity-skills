# 2D 动画岗位边界与交接

用于 Unity 原生 2D 骨骼动画的任务拆分、制作、补图、技术验证和交付。动作与时间轴沿用[动画意图合同](animation-intent-contract.md)，部件与变体沿用[制作合同](../../unity-game-2d-rigging/references/production-contract.md)，资源身份沿用[公共资源登记](shared-asset-usage.md)。本参考明确责任与交接，交付门禁使用现有控制面的合同，不增加 Work Item 类型、独立状态机或用户审批阶段。

## 岗位与所有权

| 岗位 | 拥有的职责与交付 | 边界 |
| --- | --- | --- |
| 总控／制作 | 确定使用场景、范围、依赖、任务包与生产顺序，指定动画质量负责人、实施者和独立 QA，协调冲突及用户确认 | 沿用唯一控制面；不以任务分派代替实际验收 |
| 动画导演（简单动作由设计师兼任；复杂表演独立安排） | 形成表演意图与动作方案，统筹角色表演、空间调度和节奏；协调骨骼、序列帧、Spine、3D 等路线的衔接 | 多角色、多段调度或跨类型素材协作时单独指定；不替代动画质量负责人审查，不新增 Skill 或全局状态 |
| 动画质量负责人 | 建立项目动作标杆和表演规范，审查动作设计、代表动画材料、批量动作一致性及返修覆盖 | 是现有工作流内的专业审查职责，不新增独立 Skill；与被审角色的制作者分离，不改玩法规则、不代替用户显示验收 |
| [2D 动画技术美术](../../unity-game-2d-animation-ta/SKILL.md) | 公共制作工具、导入规范、骨骼资产校验、动作与变体批量对账、依赖影响分析、回归夹具及性能测量方案 | 不默认拥有具体角色源资产；工具实现与角色制作分开分配文件和 Unity 对象，工具作者不能独立验收自己的工具 |
| [视觉资产](../../unity-game-visual-assets/SKILL.md) | 角色基准、独立部件、遮挡补全、连接区、角度／形变替换图及其资源映射；实际生图编辑交图片子代理 | 按已确认基线与拆件边界生产，不修改骨架、Clip、Controller 或玩法规则 |
| [骨骼与动画制作](../../unity-game-2d-rigging/SKILL.md) | 具体角色骨架、网格、权重、必要约束、Clip、Controller 内部结构、部件切换、挂点和角色 Prefab | 按质量目标与 TA 规范制作；不把权威玩法状态或判定放入动画，不自批独立质量检查 |
| [玩法开发](../../unity-gameplay-development/SKILL.md) | 权威玩法状态、移动／命中／伤害规则、触发时机、事件消费与角色生命周期 | 经约定接口驱动角色，不私改共享骨架、Clip、Controller 或 Sprite 切换配置 |
| [独立 QA](../../unity-game-qa-performance/SKILL.md) | 独立复验工具与角色交付，执行资产交付前和玩法接入后两轮检查，追踪缺陷和未执行项 | TA 的诊断与制作者自检只是输入，不能替代独立验证；工程 PASS 不等于显示效果通过 |
| 用户 | 确认当前版本拆件、代表动画及适用阶段的实际显示效果和实质取舍 | 技术结果、专业审查意见或沉默不能代替用户确认 |

角色所有权指具体任务内的文件和对象写入责任，不因同一人或代理具备多种能力而合并。正式 Unity 写入仍由总控排队，保持单写者；角色资产修复交原制作负责人，公共工具修复交 TA，跨界问题由总控裁决。

## 动画质量负责人

总控在既有任务交接与 F2 审查材料中写明负责人、被审角色／动作范围、参考样例与审查交付；实施包通过现有实施单元 `owner`、`fileOwnership` 分配写入责任，必要时在 `metadata` 以字符串引用责任说明或审查材料，不向严格 schema 添加未声明字段。可以由现有 QA 中具备动画专业能力的独立审查者承担；尚未有合适审查者时记录待分配，不让制作者自行签署独立结论，也不宣称该项已完成。

- **设计阶段**：导演或兼任导演的设计师把实际使用场景、角色性格与玩法窗口转为动作方案，明确目标感受、适用的关键姿态、重心／重量感、接触、空间路径、运动弧线、节奏、跟随与收势、循环／过渡和动作可读性。按项目动作选用，不强加统一时长或固定人形表演规则；正式素材生产前向用户说明方案并取得明确确认。
- **代表动画阶段**：核对时间轴、关键姿势与事件设计是否符合目标，选择能暴露连接区、遮挡、速度、挂点和变体切换风险的预览情境，提出具体到动作与时间点的返修项。
- **批量与接入阶段**：检查动作风格和力度的一致性、状态衔接、变速与重复触发适用范围，以及角色对整体玩法的表达；目标调整交总控，素材或动作缺陷交相应生产者。

代理承担此职责时，审查设计、时间轴、曲线／事件数据和预览材料覆盖情况，并提供供人工审片使用的检查点；不得自动分析 Unity 截图或据此判定视觉通过。实际画面的专业判断由具备相应能力的人工审查者提供，用户可以兼任。工程验证、专业审查意见与用户视觉确认分别留在既有证据中，不新增一轮用户文字审批。

## 交接顺序与完成依据

| 时点 | 交接 | 必须可复用的输入／输出 |
| --- | --- | --- |
| 动作方案确认前 | 制作／玩法 → 导演或设计师、质量负责人、骨骼、视觉、TA、用户 | 使用场景、目标感受、动作目的、视角与显示尺度、速度与操作频率、空间路径、节奏、接口／事件／位移归属；用户明确确认动作方案后才能制作真实素材；质量负责人提供动作标杆，TA 提供目标版本能力、数据／导入约束、验证入口与预算依据 |
| 正式部件生产前 | TA ↔ 骨骼制作 | 复用实际可用工具，在隔离样例验证所需资产链路；骨骼负责样例角色数据，TA 负责公共工具与诊断。没有工具或入口时如实报告缺口，不把岗位创建视为能力已实现 |
| 部件与变体交付 | 视觉 → 骨骼，TA 提供对账支持 | 已确认来源、部件／变体 ID、连接区、PPU／Pivot／局部空间与实际资源身份；骨骼回报接入和变形／切换问题，TA 回报映射或导入诊断 |
| 代表动画确认前 | 骨骼 → 质量负责人、QA、用户 | 当前版本角色与动作、正常速度及必要细节／慢放预览、时间轴和事件、已知差异、技术结果；质量负责人提供专业审查材料，QA 独立检查，用户按既有门禁确认后扩展依赖动作 |
| 完整资产交付前 | 骨骼＋TA → 独立 QA → 玩法 | 角色 Prefab、Clip／Controller 接口、挂点、变体切换与恢复约定、来源版本、质量审查意见、可复现验证命令和原始报告；当前角色的工程检查与目标项目播放回归通过交付门禁后，才正式交玩法 |
| 玩法接入后 | 玩法 → QA、质量负责人、用户 | 实际场景的输入响应、事件次数／时机、移动接触、过渡／中断、适用的暂停／对象池／多实例与预算证据；运行轮与用户显示确认完成后才能提交整体完成证据 |

TA 的工具交付须区分规格、实现、目标 Editor 实测和独立验证；命令存在或静态测试通过不代表角色可生产。交给 QA 的工具材料至少包含用途与版本、作用路径、调用入口、预期与实际结果、日志、失败／停止条件及影响范围。性能阈值使用项目已批准预算，缺失时只提供测量值与决策缺口，不自定放行标准。

缺陷在既有记录中明确对象、角色／动作／时间点、预期与实际、证据、负责人和复验范围：图像问题交视觉，绑定／动作／Controller 问题交骨骼，触发／规则问题交玩法，公共工具问题交 TA。QA 负责独立复验，质量负责人复核受影响的设计与专业意见，用户确认受影响的显示效果。只重验真实受影响内容，未运行的技术检查保持 `NOT_RUN`，缺少必需能力或输入保持 `BLOCKED`，实际失败记为 `FAIL` 并修复。

正式交付将上述责任和结果接入[骨骼资产交付门禁](../../unity-game-workflow-control/references/rigging-delivery-gate.md)。总控声明 `owners` 与当前候选，QA 提交独立复验材料；控制器回读原始工程和测试结果，失效或失败时阻断，输出具体岗位 `repairs`。总控沿用当前实施单元交办，不因诊断越过文件所有权；公共技术夹具不能替代正式角色，工程通过也不替代既有人工显示确认。
