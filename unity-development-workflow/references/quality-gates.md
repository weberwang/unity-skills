# 质量门

F0-F4 的唯一语义由全局控制面定义，本编排层不得重命名或另建漏斗。

| 门 | Unity 检查重点 |
| --- | --- |
| F0 范围与流程 | Work Item、路径、对象、基线、动作等级、单写者与适用批准 |
| F1 规格一致性 | 实际交付满足用户要求、批准范围和完成条件；GDD/TDD、契约和实施包用于提供目标与边界 |
| F2 领域质量 | 玩法、视觉、资源、音频、数值、架构、可访问性与独立审查 |
| F3 工程验证 | 编译、Console、EditMode、PlayMode、Scene/Prefab/Importer/GUID、构建与性能证据 |
| F4 高影响操作 | 外部写入、付费、真机、破坏性删除、签名、上传和发布的逐对象批准 |

F3 测试通过不能覆盖 F0 越界或 F1 实际需求未满足；F4 也不能补签已经发生的副作用。合同与实现细节有差异时，按实际完成情况判断，无需为了验收回改合同。普通产品或视觉取舍记录为 `USER_DECISION`，不混入操作批准账本。

## 测试等级

- T0：只检查文案、注释或无运行时影响的微小变更。
- T1：改动直接相关的最小测试、类型检查或 lint。
- T2：受影响模块的单元/集成测试、类型检查、lint 与必要构建。
- T3：全量测试、全量构建和关键流程冒烟；仍不自动授权设备、发布或外部写入。

实施后先记录推荐等级、理由、覆盖和命令，再自动执行。所有 PASS 必须对应当前实际交付、执行环境和原始证据，不计算或校验 SHA；`FAIL`、`BLOCKED`、`NOT_RUN`、未知或已不能证明当前行为的结果不能充当通过。截图由用户检查，未获明确自动视觉验证授权时代理不分析截图或判定视觉通过。
