# Unity 游戏内文案

本指南覆盖 HUD、按钮、弹窗、奖励、Toast 和状态反馈中的交互与状态信息。它复用现有 V0–V4 阶段、阶段人工确认及美术质量/动态体验验收，不新增文案审批门、Schema、关键词计数器或词库门禁。

## 表达原则

- 优先用图像、图标、数字、符号和视觉状态传达奖励、消耗、数量、倍率和进度；文字只补充玩家无法直接理解的信息。
- 对含义清楚的图标不重复附标签；必要文案使用短名称、动作或状态。首次引导、条件和有实质后果的操作保留最少但充分的说明，不为缩短而丢失语义。
- 数值与对应图标组成清楚的信息组。用 `+`、`-` 表示变化方向，倍率可用 `x{value}`，进度可用 `3/10`；余额、价格和变化量必须能从上下文区分，不能让玩家靠颜色或孤立数字猜测。
- 资源、状态与交互对象必须对应正确；按钮文字描述玩家动作，结果反馈描述已发生的状态，避免把动作和结果混为一谈。
- 同一表达在 HUD、弹窗、Toast 和奖励浮字中保持一致；只有显示状态、数据或语气确有区别时才采用不同文案。
- 纯图标控件按项目既有能力提供无障碍名称。可使用项目现有的无障碍组件或平台接入；不要声称 Unity 默认提供了未在当前工程验证过的无障碍行为。

| 意图 | 优先表达 | 避免重复解释 |
| --- | --- | --- |
| 金币奖励 | 金币图标 `+100` | 获得 100 金币 |
| 钻石消耗 | 钻石图标 `-20` | 消耗 20 钻石 |
| 奖励倍率 | 奖励图标 `x3` | 获得三倍奖励 |
| 收集进度 | 目标图标 `3/10` | 已收集 3 个，还需收集 7 个 |
| 冷却状态 | 技能图标 + `4.2s` | 技能还需等待 4.2 秒 |
| 当前余额 | 金币图标 + `100` | 你当前拥有 100 枚金币 |

示例仅展示表达方式，不限定项目资产、数值、字体或实际文案。

## 文案交接与效果图

在现有 GDD、场景规格或美术 brief 中按场景和状态区分两类内容，不把内部规则直接作为画面文字来源：

- **内部规格**：玩法规则、条件、计算方式、操作后果、设计理由和验收说明，供团队理解与实现。
- **玩家可见表达**：图像/图标、符号、允许出现的文字、动态数值格式与来源、显示条件及其适用节点。无需文字时明确为空。

### 效果图生成

V1 准备效果图生成前，列出当前候选允许显示的文字、动态数值的代表性示例和候选间共享的内容；无需为候选强行增加文字。所有候选使用相同的可见内容与代表值，只改变本次探索的视觉方案。动态数值示例帮助表达布局，不是运行时固定值。

核对清单至少能回答：

- 哪些文字明确允许出现在画面，哪些节点无文字？
- 动态数值来自哪个玩法状态或事件参数，示例值及格式是什么？
- 哪些文字与数值在全部候选中保持一致？

实际发送的图像生成提示词须分离内部规格与画面文字，指出当前场景/状态和文案来源，并包含以下约束；完整实际提示词保存在项目已有生成记录中，不新增记录字段：

```text
游戏画面优先用图像、图标、数字、符号和视觉状态表达信息。
内部玩法规则、功能说明、设计理由、验收说明及本提示词的说明文字仅用于理解，不得绘制到画面。
只绘制本次列出的可见文字和代表性数值；可见文字为空时，不添加说明、标签或占位文字。
图标与数值已表达的信息不重复改写成句子，不自行增加规则介绍、功能副标题、教学段落或提示面板。
按已定义的显示状态保留必要引导、条件和操作后果，不擅自删除这些语义。
```

提示词写了约束不代表效果图已符合要求；候选冻结前仍由用户查看画面并确认。

## 资源拆解与界面实现

- **V2 拆解**：只登记冻结目标中真实可见的文字和数值，不从 GDD 或设计理由追加说明节点。节点的显示内容与来源指向玩家可见表达；图标、皮肤不附加业务说明。
- **文字来源**：按[文字路线判定](visual-decomposition-routes.md#文字路线判定)区分低显著性系统文本、固定美术字图与可复用字形风格。路线变化不删改文案，系统文本保留独立拆解编号，动态数值与本地化保持可变；既定字形和效果不得在实现时静默简化。
- **V3 组合**：按已确认文字路线装配；系统文本使用项目选用的 uGUI/TextMeshPro（TMP）或 UI Toolkit `Label`/`TextElement`，固定美术字图、复用字形与效果依赖按各自资产路线接入，文案语义由原功能组件保留。动态数值和本地化文字来自同一玩家可见表达及真实玩法数据，不直接绑定 GDD、brief 或验收描述。动态/本地化文字不烘焙进固定图片。
- **V4 运行**：验证正常运行与适用的重复反馈、事件峰值、同屏叠加情境中，文字、数值、条件和来源是否正确；沿用[美术质量合同](art-quality-contract.md)和[阶段人工确认](../../unity-game-workflow-control/references/stage-confirmation.md)，不以本指南取代既有人工验收。

消费时按以下约定保持显示内容与运行状态一致：

- 动态数值读取权威玩法状态或已确认的事件参数；效果图代表值只用于表达布局，不作为实现常量。
- 数值格式、单位、正负号、倍率和精度按玩家可见表达及项目现有本地化规则转换；不要通过拼接内部调试说明补足上下文。
- 同一状态在首次进入、数值变化、暂停/恢复或事件重播后仍应显示当前真实值；按 Work Item 的行为范围验证适用状态。

Unity Localization 项目使用现有 String Tables 与插值方式维护相同表达和显示条件；未采用该包的项目沿用已有本地化方案。不要把图标/符号重新扩写成解释句。逐项验证五种语言 `en`、`zh-CN`、`ja`、`ru`、`es`：

- 检查每种语言的实际必要翻译、字体回退、容器适配及单行/换行策略。
- 用实际必要翻译中占用空间最长的表达及合理边界输入检查布局、换行并确认无截断；最长表达按具体节点和显示状态判断。
- 不为适配凭空增加说明段落；遇到空间不足时先按现有布局与文案取舍流程处理。

按当前项目 UI 技术和可用的无障碍实现检查图标控件名称、焦点与必要反馈；没有实测的辅助技术支持标记为未验证。

## 检查与返修

- 生成前核对实际提示词是否分离可见内容与内部规格，并明确禁止自行增加说明文字。
- 实现时核对文本配置、绑定来源和适用状态是否对应冻结表达与真实数据；不以字数、关键词或 `copy_style` 字段判定语义合格。
- 候选冻结前、V3 组合和 V4 运行均提供实际画面与检查点：查找未列出的文字、重复解释，确认数值归属清楚且必要条件和操作后果完整。
- 显示效果由用户人工检查并确认；复用现有阶段与美术验收确认，不新增独立文案返修确认。代理不得自动分析截图或替用户判定。
- 已冻结参考中的文字不擅自删除或改写；用户明确要求修改时，按其范围更新受影响目标、拆解和实现后继续验证。
- 不通过隐藏文字、缩小字号或把整屏内容烘焙进位图掩盖问题；动态数值与本地化文字保持运行时内容，不烘焙进固定图片。
