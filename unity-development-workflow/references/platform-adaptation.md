# 平台选择与适配

## 何时读取

G0 确定目标平台、S00/G1 选择主开发平台、G2 完成各平台适配或 G3 生成候选包与设备矩阵时读取。平台集合必须来自用户需求，不因模板、当前开发机或已有 Windows 工具而自动推断。

## 平台选择门禁

1. 先由 `$unity-game-grilling` 分别询问 Windows、Android、iPhone/iOS 与 iPad/iPadOS 的目标用户、发行渠道、设备覆盖、方向、输入、性能、联网与商业能力。
2. 在 `project-profile.delivery.targets` 中只保留用户明确批准的平台，每个平台拥有独立适配配置；未选择的平台不执行构建、资源生产、设备验收或发行工作。
3. `primaryDevelopmentPlatform` 只决定 S00 和 G1 的首个可运行构建，必须属于批准平台集合，不能代替其他目标平台的 G2 适配与 G3 验收。
4. 平台集合、主开发平台或适配配置变化会使相关构建、平台报告、候选包、设备矩阵和下游批准失效，必须回到 G0 重新确认。

## Windows 适配方案

- 使用 `WINDOWS_STANDALONE`，覆盖窗口化与无边框全屏、可调整窗口、DPI 缩放、焦点切换、暂停恢复和多显示器边界。
- 输入至少按批准范围覆盖键鼠与手柄；检查热插拔、焦点导航、按键提示切换和退出路径。
- 2D 竖屏固定设计高度、横屏固定设计宽度；扩展区域使用依据 Visual Bible 生成的无交互纯视觉边带，不得出现黑边。
- 针对批准的最低、推荐或参考 PC 档位记录 CPU、GPU、内存、操作系统、分辨率、窗口模式和性能证据。
- Windows 预检可使用 Toolkit 的 `uwt_delivery_preflight`，正式构建仍使用 unity-mcp `manage_build`；该工具的通过不能代替 G3 设备矩阵。

## 移动端适配方案

移动端共同要求：UI Toolkit 与游戏画面处理安全区、刘海/挖孔、圆角、系统栏、横竖屏、旋转和尺寸变化；交互目标、字号和间距服从触控可用性。输入以触控为主，按批准范围覆盖点击、拖拽、长按、多点触控、手势冲突、软键盘、系统返回或系统手势，不得依赖悬停和右键。所有目标都检查前后台、音频中断、权限拒绝、低内存、资源恢复、安装升级、离线、网络切换、热状态和耗电。

### Android

- 可分别批准 PHONE、TABLET 或两者；每种批准形态至少有一个设备档位。
- 使用 Android BuildTarget，按发行渠道生成 APK 或 AAB，并验证安装、升级、卸载、系统返回键、权限和机型图形 API 差异。
- 横竖屏同时进入范围时必须启用并实测自动旋转；只选单一方向时不得从另一方向测试推断通过。

### iPhone / iOS

- 设备形态固定为 PHONE，独立覆盖目标 iPhone 尺寸、安全区、系统手势、前后台、音频中断、Metal 性能、签名和 IPA 安装。
- 必须使用 macOS、Xcode、有效证书与目标真机；缺少任一条件时标记 `BLOCKED`，不得用 Editor 或 Android 结果推断通过。

### iPad / iPadOS

- 设备形态固定为 TABLET；即使与 iPhone 共享 Unity iOS BuildTarget，也必须拥有独立平台配置、适配报告、候选 manifest、设备档位和验收结论。
- 独立验证横竖屏、安全区、平板布局密度、触控距离，以及用户批准范围内的分屏、窗口尺寸变化、鼠标或触控板输入。
- 使用 macOS、Xcode、有效签名与目标 iPad 安装 IPA；iPhone 真机结果不能替代 iPad 验收。

## 阶段输出

- G0：状态为 `APPROVED` 的平台集合、主开发平台和每个平台的适配字段。
- S00/G1：主开发平台空壳与垂直切片构建，证明基础架构可运行。
- G2：每个批准平台恰有一份 `platforms.adaptation-complete` PASS 报告，只覆盖编译、参考配置布局、输入映射、生命周期事件模拟和静态预算。不得安装或启动 Player，也不得使用设备档位或目标设备性能结果；G2 `PASS` 是研发完成标志。
- G3：每个批准平台恰有一个候选主制品；此时才执行安装、升级、启动、设备输入、生命周期、视觉、性能、热状态、耗电和稳定性验证。最终设备报告覆盖全部批准平台、各平台设备档位与全部批准场景，并逐用例绑定所属平台候选制品；`performance.pass` 也在本门逐平台提交。

## 失败与恢复出口

- 用户未批准平台集合：保持 G0 `WAITING_APPROVAL`，不得默认选择 Windows 或移动端。
- 平台工具链或设备缺失：对应平台标记 `BLOCKED`，其他平台可准备证据但不能据此放行整个多平台产品。
- 某平台适配失败：只回退该平台的实现与报告；共享代码变化时重新评估所有平台。
- G3 候选制品与设备报告哈希不一致：隔离候选包并重新构建、安装和验收，不得改写报告哈希。
