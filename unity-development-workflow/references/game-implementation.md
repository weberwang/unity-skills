# 游戏实现闭环

## 何时读取

进入 G1 垂直切片或 G2 场景制作，准备把批准需求变成可运行 Unity 实现时读取。

## 输入

- 已批准的 GDD 增量、TDD、当前版本拆分决策、模块清单、场景 manifest 与验收条件。
- S00 公共接口、Visual Bible、资源登记和可用 Unity MCP 工具组。
- 当前测试、性能预算、发行约束与占位资源清单。

## 执行步骤

1. **冻结实现增量**：验证 `decomposition-plan` 已获用户确认，场景与模块仍在批准集合中，再记录玩家行为、可观察结果、依赖、排除项和测试点；未批准需求或拆分不进入实现。
2. **建立技术骨架**：先完成场景入口、状态、输入、配置、存档边界、生命周期与测试入口，使干净环境可编译并能生成开发构建。
3. **建立资源依赖**：在编写表现前列出图片、模型、动画、VFX、字体、音频的用途、状态、规格、锚点/枢轴、九宫格、导入设置、Addressables/Resources 地址和预算。
4. **分流视觉资源**：每个场景严格完成 A1 实际可查看草图/灰盒及结构确认、A2 高保真精确版本确认、A3 已确认原图的完整编号资产地图确认和逐项独立生产。2D 位图按地图条目独立生成或重绘、审核、导入和验证，禁止裁切效果图或整图铺底；3D 几何和贴图材质分别交给 `$unity-game-3d-modeling` 与 `$unity-game-3d-texturing`，复杂任务按 DCC 移交。
5. **实现核心规则**：规则、状态、输入、表现、平台服务和可调参数解耦；纯规则实现可与视觉资源处理并行。
6. **接入正式资源并清理低保真对象**：只有 A3 全部条目获得当前版本验证后，才能按 A1 结构和 A3 槽位映射执行 A4，拼装正式 Prefab/Scene/UXML/USS；效果图、联系表、标注图、裁片和被取代版本不得进入运行时。完成后删除全部草图、灰盒组件、占位 Mesh/Sprite/Material 和临时低保真对象，清理序列化、场景、Prefab、地址和登记引用；保留非运行时审计证据。
7. **完成集成验证**：先验证运行时低保真对象与残留引用已清零；清理验证为 `PASS` 后才可标记 `ASSEMBLY_VERIFIED`。随后验证核心循环、重开、暂停恢复、前后台、分辨率/窗口变化、资源失败、输入设备切换、离线和适用的存档异常；逐场景检查摄像机、光照、缩放、动画、九宫格、安全区、采样溢色和资源释放。清理验证或其他必需证据缺失时不得标记 `DONE`。
8. **完成测试与构建**：运行相关 EditMode、PlayMode、冒烟和主开发平台开发构建，在目标硬件或明确等价环境记录加载、帧率、内存、GC、Draw Call、纹理与包体证据；G2 再为每个用户批准平台执行其独立适配方案。
9. **提交实现证据**：记录变更路径、实际命令、测试/构建结果、正式资源清单、Editor 固定机位截图、剩余限制与阻断项，并更新场景状态。研发阶段禁止产生实机截图或设备验证结论。

## 子代理角色与并行边界

- 架构、玩法规则、资源准备、音频准备和测试设计可在不重叠写路径下并行。
- 同一 Unity 项目的场景、Prefab、ScriptableObject、项目设置和共享状态正式写入串行执行。
- 资源问题由视觉/音频角色修复，玩法重新接入，QA 只复核受影响路径；开发代理不得自批。
- 3D 建模代理只写几何/LOD/Collider/模型 Prefab，贴图代理只写已冻结 UV 下的贴图/材质；共享 Prefab、DCC 工程和场景由单一集成者写入。

## 所需锁与 Unity 权限

- 写 Unity 前显式绑定唯一实例，并取得当前增量拥有路径和 Unity Editor 独占锁。
- 编译、导入、域重载、PlayMode 或未保存状态期间不写入。
- DCC 工程、模型源和导出目录采用单写锁；先释放 DCC 锁，再取得 Unity AssetDatabase、模型、材质、Prefab 与场景锁，禁止不同代理交叉持有两侧锁。
- 默认在当前工作区使用互斥模块所有权，并串行执行 Unity 正式写入；只有用户明确要求时，多个并发写入者才可使用独立 Worktree。

## 机器可读输出

按需更新 `scene-manifest.yaml`、`asset-register.yaml`，并输出草图/结构证据、编号资产地图、结构化装配、清理验证和增量报告；报告包含范围、代码入口、资源依赖、变更路径、已删除低保真对象与引用扫描、测试、构建、性能、视觉证据和阻断项。Codex 直接编排，不维护本地任务状态机。

## 通过条件

- 代码可运行，验收行为实际通过，正式资源可追溯，主开发平台构建可复现，且批准平台集合的 G2 适配未被主开发平台结果替代。
- Unity Console 无未解释新增错误，必需测试与性能检查有当前版本证据。
- 正式拼装后的运行时灰盒、占位 Mesh/Sprite/Material、临时低保真对象及其引用全部清零，清理验证为 `PASS`，`ASSEMBLY_VERIFIED` 与 `DONE` 未越过该门禁。
- 已确认结构节点及稳定 ID 保持不变，`prefab-structure`、预览和批准记录等审计证据可用于上游回退重建。

## 失败与恢复出口

- 代码或测试失败时返回责任模块，只重跑受影响检查及下游检查。
- 资源规格、来源版本或导入设置变化时将依赖增量标为待复核，重新查重、审查和运行验证。
- 上游需要回退时从审计证据重建灰盒或占位布局，不得在运行时 Prefab/Scene 中保留低保真资产；清理失败时回到 A4 修复并重验。
- 3D 拓扑、UV、材质槽、骨骼、LOD 或 Collider 边界变化时使相应贴图、材质、动画前置、Prefab 和实机证据待复核；MCP/DCC 能力不足时输出移交包并阻塞，不以降质近似放行。
- S00 公共接口不足时回到模块规划；未满足两场景复用证据的能力留在当前场景。
