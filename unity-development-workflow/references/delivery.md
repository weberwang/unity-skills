# Windows 交付

## 何时读取

全部场景冻结且全局回归通过后，准备 Windows 构建、发布包或交付报告时读取。

## 输入

- 已通过的全局质量报告、冻结场景和发布版本标识。
- Windows 构建配置、输出目录与已批准视觉/性能证据。
- 发布说明、已知问题、回滚目标和用户授权范围。

## 执行步骤

1. 预检版本、场景列表、Windows 目标、Build Profile、脚本后端、发行方式、输出目录和剩余磁盘空间。
2. 显式绑定正确的 `unity-mcp` 实例，使用官方 `manage_build` 生成 Windows 制品。
3. 在干净启动条件下检查可执行文件启动、主路径、退出和关键日志；逐场景运行 `scripts/capture_windows_runtime.py` 生成状态为 `CAPTURED` 的实机截图证据，再完成三代理复审和用户批准。脚本成功不等于视觉批准。
4. 计算制品哈希，冻结与当前版本对应的文件清单。
5. 汇总测试、性能、视觉、资源授权、第三方包许可、隐私/数据处理和安全检查，编写发布说明、已知问题、安装/卸载与回滚步骤。
6. 对发行渠道所需图标、截图、描述、分级、隐私说明、崩溃收集、联网和账号能力逐项登记；未启用能力标明关闭，不虚构审核结论。
7. 由独立交付代理核对证据、版本、哈希、候选包和发行资料一致性。
8. 未获额外授权时不得签名、上传、创建外部发布或覆盖稳定制品。Git 提交可作为可追溯输入，但不能替代构建与运行证据。

## 子代理角色与并行边界

- 报告汇总、发布说明和哈希核对可并行准备。
- `manage_build`、启动检查和稳定制品写入必须串行。
- 交付审查代理独立于构建执行代理；最终外部发布动作由用户授权。

## 所需锁与 Unity 权限

- 构建时持有 Unity Editor 与输出目录独占锁，并使用已显式绑定实例。
- 启动检查持有制品只读锁；写入发布目录需独占锁。
- 签名、上传和覆盖稳定制品属于额外权限，不从构建授权推断。

## 机器可读输出

构建前编译 `delivery-preflight.yaml` 并由 Toolkit 输出预检结果；构建后输出 `delivery-manifest.yaml`，包含项目、版本、源码修订、构建配置、制品与哈希、启动检查、带哈希质量报告引用、带哈希实机视觉引用、许可、隐私、说明、已知问题、回滚和授权。每个冻结场景必须提供与同一构建制品哈希对应、状态为 APPROVED 的 `runtime-visual-evidence`，不得用 Editor 固定机位截图代替。G3 前以 `gate evaluate` 深验整条交付引用链。

## 通过条件

- 官方 `manage_build` 成功，制品可启动且关键路径检查通过。
- 哈希、测试、性能、视觉、发布说明、已知问题和回滚信息完整。
- 制品与证据版本一致，未执行任何未授权外部动作。

## 失败与恢复出口

- 构建或启动失败时保留日志，返回质量门禁修复并重新生成制品。
- 哈希或版本不一致时隔离该制品，不得覆盖稳定版本。
- 缺少签名或上传授权时完成本地交付并标记 `BLOCKED_EXTERNAL_ACTION`。
