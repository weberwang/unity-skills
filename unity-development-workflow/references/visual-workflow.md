# 视觉工作流

## 何时读取

建立全局视觉、场景/界面草图、高保真、资产地图、单项资产或 Unity 视觉实现时读取。

## A0 全局视觉：恰好三选一

1. 根据已确认范围、平台和体验目标，生成恰好三个完整、实际可查看且具有实质差异的方向；每个方向包含世界、资产、色彩、光照、材质、相机、UI、字体、图标、动效、可读性和禁用项。
2. 三个方向分别绑定 ID、版本、SHA-256、`sourceRevision` 和生成证据，分别经过 F0 实际验证、F1 分诊和 F2 独立专业审核。
3. 任一方向失败时修订或替换并补足三个，再对变化候选从 F0 重跑。F3 只有在三者均有效时才生成恰好三个候选的比较包，可标注推荐但不得删减。
4. F4 用户明确选择其中一个；只有被选方向可冻结为 Visual Bible。选择记录与 Visual Bible 双向引用，任一绑定变化使 Visual Bible 和受影响下游失效。

## A1 场景/界面草图门

1. 每个场景或界面必须先产出实际可查看的草图或灰盒草图，不得只交文字表格。
2. 同包提供稳定节点、父子层级、渲染顺序、元素类型、交互/状态、布局、Anchor、Pivot、安全区、遮罩和资源槽说明；UI Toolkit 同时说明 UXML/USS/UIDocument。
3. 完成 F0-F3 后请求 F4 确认该精确草图与结构版本。未确认时只能迭代 A1，不得生成高保真。

## A2 高保真门

1. 只以冻结 Visual Bible 和已确认 A1 为权威输入生成高保真效果图。
2. 对真实图像执行 F0；F1 分诊；F2 由非作者分别审核视觉一致性、Unity 可实现性、UX/可读性；F3 可收敛成唯一推荐。
3. 专业审核结束后，F4 必须确认当前精确高保真 ID、版本、SHA-256 和 `sourceRevision`。任何像素、布局或结构变化都生成新版本并重新审核，旧确认不得沿用。

## A3 完整元素分析和编号资产地图

1. 只分析 F4 已确认的高保真原图，保持原图不可变；先逐区域核对所有可见元素，再用稳定编号形成完整资产地图。
2. 每项必须分类为：独立位图、批准复用、文本、Unity 图元/程序绘制、UXML/USS/矢量、材质/VFX、3D；记录对应 A1 节点、状态变体、尺寸、透明度、导入和验证规格。
3. 漏标、重号、未分类、无结构节点映射或无法解释的视觉像素均阻塞。F0-F3 完成后，F4 对资产地图形成独立确认。
4. 资产地图确认后才按编号逐项独立生成或重绘需要生产的单图；复用、文本、Unity 图元、矢量、材质/VFX 和 3D 走各自结构化通道。每项独立验证内容、透明边缘、规格、风格、导入设置和节点映射。

严禁从高保真效果图裁切、抠取、放大、修饰或重编码后充当独立资源；严禁将整张效果图作为游戏或 UI 铺底。效果图只可参考内容、构图和信息层级，正式像素必须逐项独立生产或来自已批准复用资源。

## A4 Unity 结构化还原

1. 按 A1 结构和 A3 地图，以 Scene、Prefab、GameObject/Component、UXML、USS、VisualTreeAsset、UIDocument、材质、VFX 和 3D 对象还原；不得用整图替代层级、布局或交互。
2. 逐节点核对稳定 ID、父子层级、渲染顺序、Anchor、Pivot、遮罩、资源/状态双向映射，并验证目标分辨率、安全区和交互状态。
3. 正式资源接入后删除全部草图、灰盒、占位 Mesh/Sprite/Material、临时低保真 Prefab/Scene 对象，清理序列化、场景、Prefab、地址和登记残留引用；审计预览与批准记录可保留在非运行时证据目录。
4. 通过 Unity MCP/C# Toolkit 读取稳定状态、对象、场景、Console 和登记并运行最小 Editor 验证。清理或映射任一失败均不得标记完成。

## 失效矩阵

- A0/Visual Bible 变化：受影响 A1-A4 全部失效。
- A1 草图或结构变化：A2-A4 失效。
- A2 高保真变化：A3-A4 失效。
- A3 地图变化：受影响单项资产和 A4 失效；结构级变化还使 A4 全部失效。
- 单项资源内容、GUID、地址或导入设置变化：该项验证、节点映射和相关 A4 证据失效。

## 通过条件

A0 三选一、A1 草图、A2 高保真、A3 资产地图是四个独立 F4 用户门；A4 由真实 Unity 结构与验证证据收敛。全部证据绑定同一未失效版本链，且运行时不存在草图、灰盒、占位、整图铺底或残留引用。
