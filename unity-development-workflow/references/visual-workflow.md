# 视觉工作流

## 何时读取

定义全局视觉方向，使用截图参考，生成或编辑游戏/UI 候选，处理透明素材，或进行效果图与实机审批时读取。

## 输入

- 用户视觉目标、平台限制、内容边界与已有品牌资产。
- Codex ImageGen 可用能力、候选图片、场景 manifest 和 UI 信息架构。
- 已批准版本、审查意见与实机截图；截图必须标注来源、哈希和允许参考的维度。

## 执行步骤

1. 先写全局视觉设计简报，明确受众、情绪、设计支柱、内容边界、目标设备、渲染预算和可读性要求。此时只能生成全局方向候选，不能开始场景效果图或正式资源。
2. 以 `image-generation` 的 `GLOBAL_DIRECTION` 模式生成多张相互独立的全局方向图，再制作仅用于比较的联系表。已有截图只能提供内容、构图和信息层级，不得提供色彩、材质、光照、字体、图标、笔触或成品像素。
3. 把选定方向固化为版本化 Visual Bible：记录设计支柱、世界与资源语言、色彩、材质、光照、构图、镜头、字体、图标、UI 密度、动效、可读性规则、禁用项和截图参考政策。
4. 由视觉一致性、游戏可实现性、UX/可读性三个审查代理分别评估 Visual Bible；主代理合并为无冲突、可执行且标明优先级的修改清单，按清单生成新修订并重新审查。
5. 三类审查通过后请求用户确认全局视觉。只有当前 Visual Bible 的最终审查与用户批准均有效，才可把状态设为 `APPROVED`；后续风格变更必须创建新版本并使受影响场景回到待复核。
6. 每个场景分别执行游戏效果图和 UI 效果图循环。出图契约必须引用已批准 Visual Bible，并把它声明为唯一风格权威；每轮记录接受、拒绝和已解决意见，候选版本不可覆盖已批准原图。
7. 使用截图时逐张声明用途：只可选择 `CONTENT`、`COMPOSITION`、`INFORMATION_HIERARCHY`。生成提示词和负向提示词必须明确“依据 Visual Bible 重新设计，不复制截图风格、不裁切截图成品像素”。
8. 使用 Codex ImageGen 生成或编辑位图；保留提示词、参考证据、全局视觉版本、模型、输出版本与用途。生成候选与任何截图参考的 SHA-256 相同即视为直接复用并阻塞。
9. 简单纯色背景可做透明色键处理；复杂边缘、半透明、毛发或混合背景必须阻塞并请求合适源素材，不得伪造透明结果。UI 效果图只定义视觉目标，交互 UI 必须用 UI Toolkit 实现。
10. 先读取 `mcpforunity://scene/cameras` 核对固定机位，用官方 `manage_build` 构建，再运行 `scripts/capture_windows_runtime.py` 启动 EXE、捕获实际窗口并生成 `CAPTURED` 实机证据；按同一三代理审查、修改、重构建、重新捕获和用户批准门禁对比效果图。
11. 需要运行时素材时进入资源流水线：依据已批准 Visual Bible 重新生成可生产源图，再进行拆分前审查、拆分、逐项审查和 Unity 导入。截图、联系表、场景效果图与未审拆分图都不得直接导入正式场景。

## 子代理角色与并行边界

- 全局方向候选可并行；全局视觉批准前，场景效果图和资源任务不得启动。每个候选必须是独立图片，联系表不能作为生产源图。
- 三个审查代理独立输出，不能互相覆盖结论；主代理只合并修改清单。
- 同一批准 Visual Bible 下的场景候选可并行；资源拆分只能在重新生成源图及拆分方案均通过后开始。
- 视觉生成与 Unity 写入可并行准备，批准前不得将候选写成正式视觉状态。

## 所需锁与 Unity 权限

- 图片生成只锁定各自输出路径，不需要 Unity 写权限。
- 导入已批准素材或捕获实机效果前，显式绑定 `unity-mcp` 实例并取得目标资源锁。
- 用户视觉批准是外部门禁，任何代理均无权代替。

## 机器可读输出

输出 `visual-bible.yaml`、`image-generation.yaml`、逐资源 `image-task.yaml`、Editor 固定机位 `visual-capture.yaml`、Windows 构建实机 `runtime-visual-evidence.yaml` 和逐轮 `visual-review.yaml`。Visual Bible 记录方向候选、选定方向、最终审查、截图政策与用户批准；出图任务记录风格权威、参考声明和重新生成政策；`image-task` APPROVED 必须引用 Visual Bible、重新生成证据、已批准拆分方案及与候选视觉版本一致的逐项审查。实机证据绑定场景、构建版本、源码修订、构建制品哈希、截图哈希与尺寸。

## 通过条件

- Visual Bible 已完成三类独立审查和用户批准；当前场景候选具备与该版本绑定的证据。
- 所有截图引用均只用于内容、构图或信息层级，没有复制风格或直接复用像素。
- 游戏效果图、UI 效果图和实机效果完成三代理审查及用户视觉批准。
- 正式资源由已批准全局视觉重新生成，完成拆分前审查、逐项审查、Unity 导入和运行验证；复杂透明素材未被自动降级，UI 最终由 UI Toolkit 实现。

## 失败与恢复出口

- 用户拒绝时保留版本与原因，按单一修改清单生成新候选。
- 三方意见冲突时主代理先消歧；无法消歧则向用户展示明确取舍。
- 无法证明截图只作允许用途、无法证明资源由批准基线重新生成，或参考图授权不明时，将任务标为 `BLOCKED`，不得降级为人工目测通过。
- 复杂透明处理阻塞时请求分层源文件、遮罩或干净背景素材。
