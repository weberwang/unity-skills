# Worktree 工作区隔离

## 何时读取

只有用户明确要求使用 Worktree，且同一仓库存在两个或更多并发写入者时读取。没有用户明确授权时禁止创建 Worktree，改用当前工作区内的严格路径所有权和串行 Unity 写入。

## 输入

- 当前仓库、基线分支、并发任务、模块所有权和写路径。
- 每个写入者的分支名、Worktree 绝对路径和验证命令。
- 用户允许的 Git 操作范围。

## 执行步骤

1. 先核验用户对本次任务使用 Worktree 的明确授权；缺少授权时立即返回当前工作区方案，不创建 Worktree。
2. 单个写入者、顺序任务和只读任务直接使用当前工作区，不创建 Worktree。
3. 每个并发写入者独占一个 Worktree 与分支，并明确文件或模块所有权；两个写入者不得修改同一文件。
4. Unity 项目并发时不得让多个 Editor 对同一物理项目目录写入；每个可写 Editor 只能绑定自己的 Worktree 项目。
5. 在对应 Worktree 运行任务检查，记录提交或变更路径与验证证据。
6. 按普通 Git 流程由总控或用户集成；集成后重跑受影响的 Unity 编译、测试、资源导入与场景验证。
7. 删除 Worktree 或分支前重新确认目录干净、提交已保留且目标明确。

## 子代理角色与并行边界

- 每个写入子代理只操作自己分配的 Worktree 和模块；只读审查可读取多个 Worktree。
- 共享场景、ProjectSettings、Packages、公共 asmdef 和控制面默认归单一串行写入者。
- 主代理负责所有权图与集成顺序，不让 Worktree 代替角色交接或质量门。

## 所需锁与 Unity 权限

- Worktree 只隔离文件系统与 Git 状态；Unity 内部正式写入仍需实例绑定和项目锁。
- 不自动合并、强制删除、清理 Worktree 或删除分支。
- 未获用户授权时不得提交、推送或发布。

## 机器可读输出

记录任务 ID、分支、Worktree 路径、拥有模块/文件、Unity 实例、基线提交、验证命令、结果和集成状态。

## 通过条件

- 并发写路径互不重叠，每个 Unity Editor 只写自己的项目副本。
- 集成变更可追溯，受影响质量项已在集成后的统一项目复验。
- 没有把隔离状态误报为完成、批准或已集成。

## 失败与恢复出口

- 所有权冲突时停止相关写入，重新拆分任务或改为串行。
- Worktree 不干净或提交缺失时不得删除，先保留并上报。
- 集成冲突由负责模块的写入者修复，QA 在统一项目重新验证。
