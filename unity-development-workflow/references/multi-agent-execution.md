# 多代理执行

## 何时读取

准备分派两个以上独立工作项、协调 Unity/DCC 写入或安排独立审核时读取。

## Codex 调度原则

1. 主代理保留范围、依赖、用户沟通、证据链和失效传播；子代理只在明确所有权内执行。
2. 只读调查、候选生成、测试分析和不重叠非 Unity 文件可并行；同一 Unity 项目的 Scene、Prefab、AssetDatabase、ProjectSettings 和共享登记正式写入必须串行。
3. Codex 根据当前依赖和代理运行状态直接调度，不创建或读取本地流程状态机与锁文件。
4. 单写者是编排约束：每个任务包明确所有者、允许修改路径、依赖、验收、验证命令和禁止改动；发现重叠时停止较晚写入者并重新分配。
5. 作者不得审核自己；F2 使用独立非作者审查者，F3 由总控收敛，F4 只能由用户决定。
6. 同一时间只允许一个主场景进入 A4 Unity 写入和正式验收；其他场景可以只读准备或生成不写 Unity 的候选。
7. 3D 建模、贴图和集成按“几何/拓扑/UV 边界冻结 → 贴图/材质 → Prefab/Scene 接线”串行移交；同一 DCC 工程、模型源、贴图集或目标 Prefab 只有一个写入者。
8. 默认使用当前工作区；只有用户明确要求时才使用 Worktree。Git 和 Worktree 不参与质量门。

## Unity 写入

写入前由当前单写者显式绑定唯一 Unity MCP 实例，核对 Editor 稳定、上游版本/批准和目标基线；写入后等待稳定并复读目标对象、场景、Console、登记和最小测试。任何不一致都阻塞后续写入。不得终止归属不明的 Unity/DCC 进程。

## 交接证据

每个代理报告任务 ID、执行者、结论、变更路径、命令、原始证据、风险和下一动作。报告只描述事实，不承担全局状态机或用户批准。失败任务保留诊断，由总控依据最早受影响级重新安排。

## 通过条件

所有权无重叠，Unity/DCC 正式写入始终单写，开发与审核分离，用户门未被代理代替，且每次写入都有当前前后置证据。
