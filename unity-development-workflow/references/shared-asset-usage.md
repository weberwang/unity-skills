# 公共资源登记与使用

在 V2 拆解和复用判断、V3 资源生产与导入、V4 正式接入或公共资源变更时读取。公共资源指多个组件、场景或显示层实际共同消费，或已在当前计划明确共同使用的字体、贴图、材质、图标、九宫格、Prefab、动画和音频等资源；不因外观相近就上移公共目录。沿用既有资源总表、拆解与装配合同，不新增公共资源账本、schema 或审批。

功能与场景规划时先识别共同需求、消费位置、状态、尺寸、视觉要求和差异；尚未确定外观或使用条件的项保持共享候选。V1 回对场景目标，V2 已确认同一部件且规格一致时安排一次生产、多处引用；同场景多个实例只登记复用关系，不强制迁入公共目录。不同部件不能仅因功能相同而合并制作，V3 仍须以真实产物复核。

## 记录归属

| 记录 | 维护内容与责任 |
| --- | --- |
| `docs/asset-register.yaml` | 项目资源身份与现状的唯一总表，公共与专属资源都在此登记；由当前实施包指定的资源登记单写者维护。 |
| `Artifacts/AssetRegistry/records/` 与实际导入/验证报告 | 保留独立生产、导入的事实与来源；已有 Toolkit 图片导入会写入禁止覆盖的登记记录，生产者不能并发改总表。其他资产按其实际生产工具与合同提交证据，不假定都有同一自动登记器。 |
| TDD、模块 manifest 与 Implementation Package | 记录公共资源唯一所有者、实际目录映射、生产者、共享边界和消费工作项；同一正式资源与 `.meta` 属于同一所有权单元。 |
| 各场景/显示层拆解与装配合同 | 记录本地拆解编号、资源依赖、消费节点、布局及状态；资源身份指向总表，不复制另一份公共资源定义。 |

资源总表使用既有 `id`、`type`、`purpose`、`source`、`sourceVersion`、适用的 `visualVersion`、`path`、`address`、状态、许可、验证及证据字段；导入后登记实际 `guid`、Importer、导入报告和登记记录路径。资源身份在总表为 `id`，在生产和装配中为 `resourceId`，必须一致。同一项目同一有效资源只保留一个身份和一条当前总表记录，不为每个使用场景重新登记；不同来源或独立变体不能共用身份。

总表 schema 没有 `owner`、`consumers`、`shared` 字段，不临时添加字段；所有权与消费范围使用上表中的既有交付物。`address` 沿用项目实际资源定位约定，不为登记强制引入 Addressables，也不把未配置的定位名冒充已可运行的加载入口。

`reuseResourcePlan.assetRegisterEvidence.path` 指向 `docs/asset-register.yaml`，`recordId` 指向其中 `assets[].id`，与 `existingAssetId` 一致；来源版本及生产、导入和许可事实通过该条目的版本与证据引用核对，不另建单资源登记副本。总表可更新，真实来源记录和已完成的验收证据仍保留，各消费合同引用适用的实际版本。

## V2 查库与绑定

1. 生产新资源前查询总表、当前有效生产记录和实际工程资产，核对来源版本、视觉适用范围、许可、GUID、Importer、尺寸/九宫格、字形覆盖及所需状态；相似名称或颜色不是复用证据。库资产尚未登记时先补齐事实和审查，不能直接把它当作已验收公共资源。
2. 可复用项选择既有 `REUSE` 路线，保留本场景自己的稳定拆解编号和状态，在 `visualRouteAnalysis.reuseBinding` 绑定实际 GUID、源路径、Importer 信息及 `consumerNodeIds`。需要 `reuseResourcePlan` 的图片任务同时绑定 `existingAssetId`、登记、许可、风格和 Unity 验证证据；不能从效果图裁切补成复用资源。
3. 将多个本地编号映射到同一公共 `resourceId`，在装配合同的 `assetBindings` 保留各项 `itemId`、`decompositionElementId`、资源路径/GUID、生产证据和消费节点。节点 ID 在所属场景/显示层合同内解释，跨场景通过工作项、场景和合同引用定位，不能只记录一个无上下文节点名。
4. 没有合格资源时按实际职责安排独立生产；已确定多个消费者的资源由唯一所有者统一制作，消费者等待对应资源事实和 V3 交付，不各自产出同名副本。仅为单个场景定制的资源留在本场景范围。

V2 可以绑定 `PLANNED` 资源作为生产依赖，但不能把它标为合格复用或接入最终运行。采用现有资源不会免除当前场景的拆解图与布局图确认、V3 资源验收或 V4 正式组合验收。

## V3 登记同步

生产者交付当前资源 ID、来源/视觉版本、正式路径、实际 GUID、Importer、许可与工程证据。已有 Toolkit 图片导入记录是不可覆盖的事实，技术 `PASS` 与记录中的 `licenseStatus=PENDING` 不代表许可和用户视觉确认已通过；合并者以相应独立证据更新总表，不伪改原始记录。

正式图片完成生成、透明处理、尺寸归一化和实际导入后，复核早期共享计划及新发现的共同需求，逐消费位置核对状态、尺寸、裁切/变换限制、字形和视觉目标；待人工显示确认时保持候选，不提前认定可复用。结论写入总表证据与各消费合同，不满足时保留独立资源并说明原因。已生成资产保留真实生成来源，不能因后来共用而回写成复用生产；发现共享候选不授权静默换源、跳过已确认的独立生产、删除独立产物或改写历史确认，调整按当前工作项实际变更边界处理。

资源登记单写者在当前 V3 资源交接时审查并合并有效记录，不必等到项目最终全局集成才使已合格的公共资源可查询。按资源 ID 和实际 GUID/路径对账，更新 `registerVersion`、来源与现状，保留历史事实引用；重复身份、冲突路径、记录缺失或无法对应实际资产时先修复受影响项，不能以最后写入的一份覆盖冲突。后续消费者读取总表和所引用的证据，不能只凭生产者口头说明或未合并的候选认定可用。

新资源、正式替换和路径/Importer 调整在向下游交付前同步总表及受影响的拆解/装配引用；消费节点新增、移除或换绑时同步所属合同与工作项依赖。共享源、字体覆盖、材质效果或切片发生变化时，由唯一所有者更新，并依据实际消费关系安排资源级重新导入验收和受影响的 V4 组合重验，不以登记成功代替组合通过。

## 使用与局部状态

场景通过项目已有序列化引用或实际加载方案消费登记资产，并回读真实引用。公共资源保持单一来源，场景只保存本地实例、布局和状态；不复制 `.meta`、不私改共享 Texture、Material、Mesh、字体或 Prefab 源。场景特有外观用明确的实例参数或独立登记变体表达；确需变更公共源时交由资源所有者，不能借局部状态操作影响其他消费者。

各消费工作项在既有运行/组合证据中按组件及适用状态记录实际使用的资源版本、路径/GUID、实例和结果，连同拆解编号及消费节点定位到所属场景/显示层；多个实例不只记录首次使用。仅存在计划或资源已加载不能证明每个状态都正确消费，未执行项保持未验证，资源级通过不代替各消费位置的组合验收。

文本与填充分拆后也遵守这一规则：共用字体/字形图集、材质、纹理填充与九宫格按实际资产登记；不同按钮的文字内容、进度比例、显隐和选中颜色仍由各自功能组件管理。纯原生颜色、圆角、排版等没有独立资产文件时，复用已有 Visual Bible、TDD 或样式配置及其实现单元，在拆解中记录消费关系，不虚构资源文件、GUID 或导入记录；样式若实际存为 USS、Prefab 或配置资产，则按真实产物登记和引用。

例如两个显示层共用字体和发光按钮底板：总表各登记一条公共资源，各层的文字/底板保留独立拆解编号并绑定相同资源身份；字号、文案、按钮尺寸和状态由本层组件控制。基础纯色填充只复用已确认样式参数，不为每个颜色生成一张公共贴图。

## 交接检查

- V3/V4 对账资源身份、当前版本、许可、实际路径/GUID、Importer/切片/字形、合同引用及消费节点，拒绝未登记、未验收、授权未满足或已被替换的最终引用；缺项保持未完成，不推定通过。
- 公共资源变更后根据实际消费关系检查受影响的组合、状态、本地化、裁切及加载；删除或移动前从场景、Prefab、配置、字体回退、图集、实际加载入口和构建配置核对全部消费者与间接依赖，未能确认的共享源保留，不因一个场景已不用就删除。移动/重命名仍按 AssetDatabase 与现有权限边界执行。
- 记录检查与实际消费检查分开。现有 schema 只能证明结构合法，不能自动证明总表唯一、跨合同一致或 Unity 已消费；由当前执行者提交真实对账/回读证据，显示效果仍由用户人工确认。
