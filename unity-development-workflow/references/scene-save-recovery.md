# 场景保存与弹窗恢复

适用于 Editor 报告 `editor.scene-dirty`、切换场景前发现未保存修改，或 Unity 已显示“是否保存场景”对话框。项目发现阶段只记录脏场景，不执行保存；正式恢复属于当前 Work Item 的 Unity 写入。

## 自动处理

1. 由单写者确认唯一 Editor、Implementation Package 和全部已加载脏场景的路径、所有权与改动来源。只有本次任务写出的已命名场景，且其路径同时位于 Work Item 与实施包的允许范围内，才可自动保存。未命名场景、其他人或来源不明的修改、基线漂移及所有权重叠保持 `BLOCKED`，不猜测保存或丢弃。
2. 每次完成一批 Scene/GameObject 修改后，在打开其他场景、切换 BuildTarget、测试、构建或调用要求稳定 Editor 的 Toolkit 命令之前，按 `unity:unity-cli` 当前发现的能力保存本次修改的场景。单个活动场景可用已发现的场景保存命令；只有全部待保存场景和资源均属当前实施包时，才能使用保存全部命令。不得通过“不要保存”绕过弹窗。
3. 保存后重新读取场景路径、脏状态、序列化内容与 Console，确认目标场景不再脏且引用仍符合实施包，再继续原操作。保存命令返回成功或弹窗消失都不能单独作为验证通过的证据。
4. 若弹窗已出现且 Unity CLI 仍可操作，先按插件命令恢复；命令被模态对话框阻断时，可用桌面 Unity 的可见 UI 操作读取弹窗内容，仅在第 1 步条件全部成立且按钮明确对应“保存”时确认。无法核实按钮、保存路径或改动来源时停止并报告具体场景，不做盲点、强制关闭 Editor 或循环重试。

同一阻断只自动恢复一次；保存或复读失败后保持 `BLOCKED`，记录场景路径、原始错误和已执行动作。`EditorStabilityGuard` 继续阻断未清除的脏场景，不能放宽其门禁。
