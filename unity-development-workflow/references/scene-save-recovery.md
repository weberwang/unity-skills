# 场景保存前置检查

每次执行可能切换、关闭或卸载场景的命令之前，只检查当前任务修改的目标场景。测试、构建、切换 BuildTarget 和要求稳定 Editor 的 Toolkit 命令也执行同一检查。项目发现阶段只记录该场景状态；持有当前 Work Item 与 Implementation Package 的单写者负责保存。不得扫描或保存其他已加载场景。

## 命令执行顺序

1. 先确认唯一 Editor、实施包允许路径、Unity 对象所有权和单写者；通过 `unity:unity-cli` 当前发现的只读能力检查目标场景的路径、活动状态和脏状态。
2. 目标场景未修改时跳过保存。仅当它是当前活动的已命名场景、路径同时落在 Work Item 与实施包允许范围内，且脏修改属于本次任务时，才调用插件当前命令目录中的单场景保存命令。命令显式绑定目标项目，不依赖窗口焦点；活动场景不匹配时保持 `BLOCKED`，不得先切换场景或调用保存全部命令。
3. 保存后只重新读取目标场景的路径、脏状态、序列化内容与 Console。确认目标场景已保存、引用符合实施包，再执行原本的切换或后续命令。命令返回成功本身不构成保存完成证据。

每批目标场景的 Scene/GameObject 写入完成后执行一次上述检查和保存，不能等到 Unity 弹出“是否保存场景”才处理。未命名场景、他人或来源不明的修改、基线漂移、所有权重叠、命令缺失或保存复读失败时保持 `BLOCKED`，记录目标场景与错误，不执行可能弹窗的原命令；不得自动选择“不要保存”、点击弹窗或强制关闭 Editor。若 `EditorStabilityGuard` 因其他场景的脏状态阻断，报告外部阻断，不扩大检查或保存范围。
