# 3D 角色建模、贴图、绑定与动画交接

建模、贴图、绑定和动画源制作统一使用 Blender MCP。使用现有 Work Item、Implementation Package、V0-V4 和 F2/F3；下列清单是角色交接依据，不新增状态机、Schema 字段或审批阶段。模型与贴图继续执行[共同交接](../../unity-game-3d-texturing/references/model-texture-handoff.md)，角色在此基础上增加骨架、蒙皮和动作依赖。

## 职责与文件所有权

| 角色 | 拥有的内容 | 输入与限制 |
| --- | --- | --- |
| [建模](../../unity-game-3d-modeling/SKILL.md) | 生产网格、拓扑、顶点顺序、UV、法线、材质槽结构、BlendShape 目标几何、各 LOD 几何与静态模型导出 | 按动作范围准备关节边流和拆件；绑定/动画需要改几何时回到本角色，不在下游暗改 |
| [贴图](../../unity-game-3d-texturing/SKILL.md) | 材质节点、绘制图、主通道与打包图、纹理源和贴图导出 | 模型、UV、骨架、权重只读；只向既有槽位赋材质，沿用实际槽位/LOD 用图与法线基准 |
| [绑定](../../unity-game-3d-rigging/SKILL.md) | Armature、静置/绑定姿势、骨骼名/层级/局部轴、控制与变形骨映射、Root/挂点、权重、校正驱动、各 LOD 蒙皮、带骨架/蒙皮的角色导出 | 不能修改生产拓扑、UV、槽位或 BlendShape 目标几何；校正形状由建模提交，绑定管理其驱动。角色蒙皮 FBX 由本角色导出，替代静态导出作为该角色的运行时模型来源 |
| [动画](../../unity-game-3d-animation/SKILL.md) | 动作方案、Actions/曲线、NLA 使用范围、表演/节奏、根运动轨迹、事件标记、导出骨架动画烘焙和逐 Clip 动画导出 | 绑定输入只读，不改 rest pose、bind matrices、骨架名/层级、权重或控制 Rig；驱动已有 BlendShape 通道，不创建目标几何。结构缺陷退回绑定 |
| Unity 集成单写者 | ModelImporter/TextureImporter、Avatar、AnimationClip 设置、Material/Renderer、角色内部 Animator 与资源级 Prefab | 由实施包明确到绑定/动画/集成负责人，执行[导入合同](3d-character-unity-import.md)；玩法拥有触发、权威状态、命中/伤害和位移裁定，正式场景接入属于 V4 |

各角色保存版本化派生 `.blend` 和可编辑依赖，原始输入只读。同一源、导出目标和 Unity 对象同时只允许一个写者；不能通过复制派生文件绕过网格/骨架所有权，也不能从纹理或动画派生文件覆盖正式蒙皮角色。项目内部可引用同一资产，但接收记录必须绑定实际文件和候选，不凭“最新版”猜测。

## 建模与贴图交给绑定

- 角色/资源 ID、候选与实际 `.blend`、对象/Collection、运行时网格及当前导出、源路径与许可。
- 单位、上轴/前轴、Pivot、变换、对称/拆件、三角化与法线/切线策略；明确关节、极限姿势、装备/附件、面部与变形需求。
- 网格/顶点顺序、UV 通道、槽位/面分配、各 LOD 几何与用图、目标平台的骨数/权重/蒙皮预算，以及已有骨架/BlendShape 的来源和归属。
- 按[模型与贴图共同交接](../../unity-game-3d-texturing/references/model-texture-handoff.md)提供已有贴图、通道语义、Material/Shader 映射、颜色空间和烘焙基准；尚未制作的贴图明确标为待交及其责任人，不用占位图冒充正式贴图。网格/UV/槽位与变形范围已确定即可开展骨架/蒙皮，不以正式贴图完成作为绑定启动前置。材质连续性与最终角色外观验收须等待实际贴图后进行，绑定只读使用，不重新制作贴图。

模型还是 blockout、关节拓扑无法支持已确认动作、目标几何/UV/槽位未明确时，只暂停相关绑定/动作，不用自动权重或材质遮挡补救。贴图可与绑定在稳定模型的不同派生文件中独立推进，但不能同时修改同一物理文件或依赖尚未确定的几何。

## 绑定交给动画

| 交接项 | 必须提供与核对的内容 |
| --- | --- |
| 骨架身份 | 角色候选、Rig `.blend`、Armature/网格、骨架版本、骨名/层级/局部轴、rest pose 与 bind 数据、运行时骨架和对象路径 |
| 控制接口 | 控制骨到变形骨映射、约束/驱动/IK-FK 切换、空间切换、极向/接触控制、Root 与骨盆分工、旋转模式和可动画属性；不可依赖未交付插件或脚本 |
| 蒙皮与形态 | 各 LOD 的权重/骨映射、影响数限制和规范化报告、零权重/非有限值/越界检查；按需的形状通道名、范围、校正驱动、骨架/形态依赖 |
| 根与挂点 | 位移/朝向来源、in-place 或位移型动作策略、运行时 Root 路径、武器/道具/特效挂点及必须导出的祖先/无权重骨 |
| 变形覆盖 | 按角色风险覆盖肩/髋/肘/膝/扭转、面部、附件与动作极限的压力姿势；技术结果和供用户检查的实际片段，已知限制不得隐藏 |
| Unity 路线 | Humanoid 或 Generic 选择及原因、Avatar 目标、参考角色 FBX、导出骨集合、轴向/比例、法线/三角化、采样/压缩预算与参考导入结果 |

动画接收时只读核对；缺骨/不稳定控制、错误静置姿势、权重或形变问题退回绑定，绑定再按需要向建模退修。未完成代表性变形检查时不能因“有骨架/能动”就扩展批量动作。

## 动画交给 Unity 集成

- 动作方案按[动画意图合同](animation-intent-contract.md)取得既有确认后制作；每个 Clip 独立记录用途、Action/slot/NLA 实际来源、开始/结束帧、FPS、采样间隔、总时长、循环接点、朝向与接触、过渡/中断、Root Motion 和事件标记。没有使用 slot/NLA 时说明实际来源，不假定当前版本动作结构。
- 交付可编辑动画 `.blend`、所需 Rig 与依赖、逐 Clip 烘焙到运行时骨架的曲线、必要的 BlendShape 曲线、导出配方和实际 FBX 等产物。不要求控制骨随运行时模型导出；约束/驱动的结果必须落成当前格式实际支持的曲线，不能假定 Unity 读取 Blender Rig。
- 每个导出绑定同一骨架的实际层级、rest/bind 和 Root 策略；明确哪些文件含网格/蒙皮、哪些仅含同构骨架和动画，不能把不同 Rig 的动作文件套用同一 Avatar。
- 交付动作/事件到 Unity Clip 的映射、目标 Avatar、Animator 参数/状态/过渡/中断接口及动作负责人；事件可通知表现或玩法入口，不能在资产里自行定义伤害、命中或第二套位移权威。
- 材质图不随每个动作重建；Unity 资源级 Prefab 组合正式蒙皮角色、贴图 Material、Avatar 与 Clips，按[导入合同](3d-character-unity-import.md)记录技术证据与用户显示确认。正式场景运行、响应和生命周期属于 V4。

## 返修与依赖范围

| 实际变化 | 修复归属与重验范围 |
| --- | --- |
| 仅贴图颜色/粗糙度，模型/UV/骨架未变 | 贴图修复主通道、打包和 Material，复验相关动作下的材质显示；不无故重绑定或重做全部动作 |
| 拓扑/顶点顺序/BlendShape 几何或关节形体改变 | 建模修复；绑定检查权重/形态/各 LOD 和角色导出，贴图检查受影响 UV/烘焙，动画复验受影响变形与 Clips |
| UV/槽位/法线/三角化改变 | 建模修复；贴图按实际依赖重烘/重映射，绑定更新角色导出并核对蒙皮保持，Unity 重验相关 Renderer/Normal/材质，不默认动画曲线全部失效 |
| 骨名/层级/rest pose/轴向/Root 或绑定矩阵改变 | 绑定修复；重新交付角色和导出映射，动画重新适配/烘焙受影响动作，重验 Avatar、挂点、Root Motion 与 Prefab，不能沿用旧骨架引用宣称通过 |
| 仅权重/校正驱动或控制 Rig 改变，运行时骨架未变 | 绑定修复，动画重新检查代表动作与驱动烘焙；控制改变影响结果时重烘相关 Clips，Unity 重验蒙皮、形态与 Bounds |
| 仅时长/关键帧/事件/根轨迹改变 | 动画修复相关 Clip、烘焙与导入设置，玩法/集成重验事件次数、位移、循环/过渡/打断和生命周期；不改模型/贴图 |

问题须定位实际源、对象/骨/槽位/LOD/Clip 与复现时间或姿势，说明受影响依赖，按既有 `repair`/`return`/`revalidate` 执行。无需为目标内返修改合同或计算 SHA。保留当前候选的真实工程结果、独立专业审查和用户人工显示确认，缺任一必要部分不宣称整条角色链完成。

## 证据与边界

证据沿用现有 Evidence 与实施包 `acceptanceCommands`，保存真实文件/对象/Clip、工具版本、报告和原始结果。3D 不填写 2D 专用 `riggingDelivery`，不调用 `uwt_validate_2d_rigging` 或把 2D 检查器通过当作 3D 放行；本仓库未提供的 3D 检查命令须在项目中发现或实现后实测，不能猜命令或虚构机器报告。

截图/播放片段由用户人工检查；可自动核对权重、层级、曲线、事件和引用数据，不能自动分析截图或据此判定视觉通过。没有实际 Blender/Unity 执行时标为 `NOT_RUN`/`BLOCKED` 并列缺项。未经用户明确要求，不启动 Standalone/Player 或真机验收。
