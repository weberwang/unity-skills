# 工作流总览

## 控制面与执行面

Skill/Codex 负责范围、编排、证据链、失效传播和用户门；Unity MCP/C# Toolkit 负责 Scene、Prefab、Importer、Editor、截图、构建预检等 Unity 事实。Node 只初始化文档、计算 SHA-256、检查文件边界和封装 JSON Job。核心流程不依赖 Python 或本地流程状态机。

## 固定生命周期

1. **G0 范围/平台/模块/全局视觉**：只读发现，确认范围、平台和拆分；执行 A0，向用户提交恰好三个已通过 F0-F2 的有效全局方向，F3 组成三选一包，F4 选一后冻结 Visual Bible。
2. **G1 骨架和垂直切片**：建立 S00 共享骨架，在 Editor/PlayMode 完成一个端到端场景与主开发平台可生成构建；不安装或启动设备。
3. **G2 研发完成**：对全部场景执行 A1-A4，完成全部模块、Editor 验证、自动测试、全局回归和无设备平台适配。全部实际 `PASS` 才产生唯一 `DEVELOPMENT_COMPLETE` 结论。
4. **G3 候选包与设备矩阵**：只消费当前 G2 结果生成逐平台候选和矩阵。未经用户明确要求/授权不得发起真机、Standalone 或等价设备验收；缺少环境时保持 `NOT_RUN`/`BLOCKED`。

## 不可跳过美术主链

`A0 全局视觉恰好三选一并冻结 Visual Bible → A1 每场景/界面实际可查看草图或灰盒草图及结构说明，用户确认 → A2 基于 A0/A1 的高保真经过独立审核，用户确认精确版本 → A3 只分析已确认高保真原图，完整编号分类，用户确认资产地图后逐项独立生产和验证单图/非图片元素 → A4 在 Scene/Prefab/UXML/USS 中结构化还原，清理草图/灰盒/占位和残留引用，完成 Unity 验证`。

A1 草图、A2 高保真、A3 资产地图是三个独立用户门。禁止从高保真裁切资源、修饰裁片或整图铺底。

## F0-F4

所有对象按 `F0 实际验证 → F1 总控分诊 → F2 独立非作者审核 → F3 总控收敛 → F4 用户决定`。全局方向专项要求 F3 保留恰好三个有效候选供 F4 三选一；普通高保真可在 F3 收敛唯一推荐后由 F4 确认。

确认和审查均绑定对象 ID、版本、SHA-256、`sourceRevision`、上游证据和范围。上游变化递归作废下游：A0→A1-A4，A1→A2-A4，A2→A3-A4，A3→受影响资产/A4。默认拒绝所有失败、阻塞、未运行、未知或不匹配证据。

## 并行与写入

只读调查、候选生成和不重叠报告可并行；同一 Unity 项目的正式写入和共享配置串行，由 Codex 分配单写者，不依赖本地锁状态机。开发者不能审核自己的输出。除非用户明确要求，不创建 Worktree，不自动签名、上传、发布或真机验收。
