# 工作流总览

## 何时读取

每次启动、恢复或重新规划 Unity 工作流时首先读取；把它作为其余参考文件的阶段导航。

## 输入

- 用户目标、目标场景和交付边界。
- 当前项目路径、已有机器可读产物与证据目录。
- 用户已经明确批准或拒绝的视觉版本。

## 执行步骤

1. 先按严格执行策略，按影响选择快速、标准或发布通道并列出适用门禁；未判定项默认适用。标准/发布按“项目只读发现 → G0 候选拷问与立项 → 全局技术/视觉设计 → 模块与场景拆分拷问/用户确认 → S00 → G1 垂直切片 → G2 场景小循环 → 全局回归 → G3 Windows 交付”推进。可由证据确定的事实不得转问用户。
2. 先执行只读项目发现；失败时进入恢复出口，不得写入。
3. 形成全局技术方案与 Visual Bible；候选冻结前由 `$unity-game-grilling` 逐项确认关键取舍并生成绑定当前候选的批准记录，再取得用户视觉批准。
4. 完整回答拆分拷问，展示模块、场景、依赖、所有权、共享能力、拒绝项与恢复出口；取得用户对当前拆分版本的确认。
5. 完成 S00 共享骨架和空壳构建，选择一个代表性场景完成 G1 垂直切片，再逐场景执行 G2 小循环。
6. 每个阶段建立“输入 → 执行者 → 原始结果 → 独立审查 → 用户决定”的证据链。
7. 每个场景严格执行“P0 低保真 Prefab/Scene 结构与说明 → 用户确认 → P1 高保真游戏/UI 效果图 → 用户确认送审候选 → P2 三类独立审阅 → P3 同版本效果图完整编号资产地图 → 用户确认 → P4 各通道逐项生产并全部验证 → P5 正式结构化拼装 → 删除运行时灰盒/占位并清理引用 → 清理验证 `PASS` → 实机对比与最终批准”。Visual Bible、P0、P1、P3、3D brief/外部工具、质量阈值和最终实机/发布授权在请求用户决定前必须调用 `$unity-game-grilling`；2D 位图逐项独立生成，3D 资源分别路由 `$unity-game-3d-modeling` 与 `$unity-game-3d-texturing`。全部场景冻结后执行全局回归和 G3 Windows 交付。

任一适用门禁失败、阻塞、未运行、证据缺失或版本不符时立即停止推进。用户确认必须绑定当前对象 ID、版本、SHA-256、来源修订与范围；口头确认和代理判断不得代替用户批准。上游变化后递归作废下游，回到最早受影响门禁。

快速通道对已批准的局部低风险任务直接实现和验证，不强制维护控制面或 G0 至 G3。主代理只编排任务、维护状态、合并审查意见和请求批准；实际发现、实现、测试、视觉生成、审查与交付检查尽量由子代理承担。

## 子代理角色与并行边界

- 并行执行互不写入同一 Unity 项目的只读调查、设计候选、测试分析和报告整理。
- 串行执行同一项目的正式写入、共享状态变更和主场景验收。
- 3D 候选规格可并行准备；同一 DCC 工程、模型源、贴图集、材质、Prefab 或依赖场景只允许一个写代理。
- 开发代理与审查代理必须独立；开发代理不能自批。
- 任一时刻只允许一个主场景处于验收阶段。

## 所需锁与 Unity 权限

- 项目发现阶段只需只读权限。
- 任何 Unity 写调用前都必须发现并显式绑定唯一 `unity-mcp` 实例。
- 正式写入需获得目标资源的独占锁；共享状态需获得全局独占锁。
- DCC 工程和导出目录使用独占单写锁；DCC 写代理释放源/导出锁后，Unity 导入代理才能取得 AssetDatabase 与目标资产锁。

## 机器可读输出

输出 `workflow-state.json`，至少包含 `channel`、`gate`、`phase`、`active_scene`、`approvals`、`evidence`、`blocked_reason` 和 `next_gate`。

## 通过条件

- 当前阶段的前置门禁有可追溯证据。
- 所有适用检查均有当前版本原始证据；不存在以 `NOT_RUN`、未知结果、代理声明或 Git 状态推断的通过。
- 当前通道与任务影响匹配，未维护无关角色和交付物。
- 独立审查与用户批准状态明确，且代理未代替用户批准。
- 正式结构化拼装后，运行时灰盒组件、占位 Mesh/Sprite/Material、临时低保真 Prefab/Scene 对象及其引用全部清零，清理验证为 `PASS`；否则不得进入 `ASSEMBLY_VERIFIED` 或 `DONE`。
- 已确认结构节点、稳定 ID 以及 `prefab-structure`、预览和批准记录等审计证据保持可追溯。
- 下一阶段所需参考文件、权限与锁均已确定。

## 失败与恢复出口

- 缺少证据、实例、锁、精确版本批准或明确允许条件时按默认拒绝标记 `BLOCKED`，保持在当前阶段。
- 修复只读发现问题后从项目发现重跑；视觉被拒绝时返回对应视觉循环。
- 场景失败只回退该场景；共享骨架变化则重新评估所有下游场景。
- 上游需要回退时从保留的审计证据重建灰盒，不在运行时保留低保真资产作为回退副本。
- 3D 工具能力不足时转 DCC 移交并保持 `BLOCKED`；拓扑或 UV 边界改变时使贴图、材质、Prefab 和运行证据待复核。
