# 领域审查

领域审查属于 F2，不是第二套 F0-F4 流程。作者自检可以发现问题，但不能替代独立审查。

## 审查步骤

1. 对真实候选运行可确定的预检，保存原始结果。
2. 总控确认候选身份、范围、上游版本和送审资格。
3. 由非作者按实际风险选择架构、玩法、视觉、UX、资源、音频、数值或性能审查。
4. 修复阻塞问题并只重验受影响检查；候选未变时不得重复请求用户确认。
5. 将领域结论写入 F2，并把机器验证独立写入 F3。

全局视觉方向在项目需要探索时可以提供三个实质不同候选，但“固定三选一”不是所有项目或任务的硬门。只有剩余问题涉及真实产品/视觉取舍时请求 `USER_DECISION`；版本、哈希和文件存在不能代替用户的选择。
