# 多级漏斗审核

## 何时读取

生成、审查、收敛或请求用户决定任何视觉、结构、资产、实现或交付候选前读取。

## 固定语义

1. **F0 实际验证**：对真实候选执行可重复检查，验证文件可读、尺寸/格式/完整性、版本绑定和对象硬约束；保存原始证据。未实际运行不得写 `PASS`。
2. **F1 总控分诊**：检查候选是否在范围内、证据是否齐全、应由哪些学科审查以及应返回哪一级；不替专业审查者或用户作决定。
3. **F2 独立非作者审核**：由与作者不同的审查者完成所需学科审查。视觉对象至少覆盖视觉一致性、Unity 可实现性、UX/可读性；意见绑定精确候选。
4. **F3 总控收敛**：合并重复意见、区分阻塞/必须修改/建议，确认候选数满足对象策略，形成一个待 F4 决定的版本化包。F3 不是用户裁决。
5. **F4 用户决定**：用户对当前包中的精确对象明确选择、确认、要求修改或拒绝。代理不得代批。

## 候选数策略

- `GLOBAL_DIRECTION`：F0-F2 必须分别处理三个完整且具有实质差异的候选。任一候选失败，补足或修订该方向并从 F0 重跑。F3 输出必须恰好包含三个有效候选，可推荐一个但不得收敛为一个；F4 用户从三者中明确选一个。
- `SCENE_HIGH_FIDELITY`、`IMPLEMENTATION_VISUAL` 和其他普通对象：F0/F1 可接收多个；F2/F3 可收敛一个唯一推荐；F4 确认当前精确版本。
- `SCENE_SKETCH` 与 `ASSET_MAP`：F3 可形成一个完整包，但 F4 分别构成独立用户门，不能被高保真确认或其他批准替代。

全局三选一是唯一候选数例外，不是质量例外：三个方向都必须完成必要预检和专业审查。三个方向只换配色、文案或局部装饰不构成实质差异。

## 证据与回退

每个阶段记录输入/输出对象 ID、版本、SHA-256、`sourceRevision`、审查者、结论范围、原始证据和返回级。任一候选内容变化产生新版本并从 F0 重跑；只改变专业审查材料时回到 F2；F3 包内容变化使 F4 失效。上游批准失效时，其下游漏斗结论同步失效。

`PASS` 只表示该层职责已完成，不表示 F4 已确认。`FAIL`、`CHANGES_REQUIRED`、`BLOCKED`、`NOT_RUN` 或未知均停止下游。作者不得审核自己，F1/F3 总控不得冒充 F2 独立审查。

## 通过条件

- F0-F4 顺序完整，身份与证据分离。
- `GLOBAL_DIRECTION` 的 F3 包恰好三个有效候选，F4 选择其中一个。
- 普通高保真在专业审查后才请求 F4 确认精确版本。
- 所有确认绑定当前对象，且没有以旧批准、口头“继续”或代理意见代替用户决定。

## 失败与恢复

- 硬约束失败回 F0；证据或范围错误回 F1；专业问题回 F2 或其最早内容生产级。
- 用户要求修改时依据影响返回生产级，生成新版本并重跑受影响漏斗。
- 候选无法补足为三个有效全局方向时保持 `BLOCKED`，不得降为二选一或唯一推荐。
